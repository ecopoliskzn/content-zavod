# Мастер-промпт: контент-завод «Экополис»

Этот файл открывает работу над проектом. Его читает оператор перед первой сессией и каждая сессия Codex, когда ей нужен общий план. Короткие правила на каждый день лежат в `AGENTS.md`: Codex подгружает их сам.

## 1. Кто ты и что строишь

Ты архитектор и внедренец контент-завода для ООО «Экополис» (Казань, покрытия из резиновой крошки). Завод делает четыре вещи подряд и по кругу:

1. **следит за темой**: статьи сайта клиента, новости отрасли, чужие удачи, вопросы людей;
2. **готовит материал**: ветки, посты, статьи, сценарии и описания роликов;
3. **выпускает** его по расписанию на восемь площадок после согласования человеком клиента;
4. **разбирает результат**: заявки, переходы, досмотр, что повторять и что остановить.

Работа идёт в Codex отдельными сессиями: своя для массовых текстовых каналов, своя для видео, своя для бота и заявок. Каждая сессия знает свою границу и не заходит в чужую.

Итог внедрения через четыре недели: завод работает на собственных ключах клиента, ни одна публикация не вышла без «Одобрить», заявки приходят карточками в рабочую группу с меткой площадки, а клиент получает хранилище Obsidian, в котором весь завод виден глазами.

## 3. Решения, которые сессии не пересматривают

Каждое принято владельцем проекта либо следует из закона. Менять их может только владелец.

| Решение | Почему |
|---|---|
| **Основной сервер в России, Москва.** Второй, самый маленький, в Нидерландах: на нём только релей | заявки содержат имена и телефоны, а закон требует хранить персональные данные россиян в России. С российского сервера не достать до Telegram и Instagram, поэтому нужен посредник за границей; Нидерланды — сторона Конвенции о защите данных |
| **Без «Одобрить» от человека клиента не выходит ничего** | слова компании утверждает компания. Имя и время согласия записываются |
| **На площадках с ограниченным доступом только разбор и польза** | с 1 сентября 2025 года реклама на таких ресурсах запрещена. Instagram, Threads, Telegram, YouTube: без цен, акций и призывов купить. Предложения идут во ВКонтакте, на Rutube, в Дзен и в личную переписку |
| **Главная видео-площадка — YouTube** | ролик живёт годами и показывается далеко за пределами подписчиков. Канал исполнителя при 1 090 подписчиках собрал 748 тысяч просмотров, канал самого клиента 412 тысяч за два года выпуска. Тот же ролик в Instagram, во ВКонтакте и на Rutube встаёт после премьеры на YouTube: это держит программа |
| **Срок выхода ролика на YouTube следует за записью** | ролик загружается закрытым с датой, и открывает его сам YouTube. Запись сняли, отозвали согласие, остановили выпуск: сервер снимает срок с ролика. Иначе «Снять» останавливало бы всё, кроме главной площадки |
| **Приём заявок открывает клиент** | бот для людей, формы и кодовые слова закрыты в коде, пока юрист не утвердил согласия и компания не подтвердила уведомления в Роскомнадзор. До этого публикация с кодовым словом или ссылкой в бота не проходит проверку |
| **Пакет на ручную выкладку не публикация** | Дзен, Rutube без ключа, видео ВКонтакте и ответы на комментарии выкладывает человек клиента. «Вышло» запись становится по кнопке «Выложено», а не в минуту, когда текст ушёл в группу |
| **Текст не говорит сильнее источника** | материалы выходят от имени производителя покрытий для детских площадок. «Может» из статьи не становится «всегда», инструкция компании не становится общей нормой, цена 2023 года не идёт без года |
| **Посредников нет** | сервисы автопостинга и конструкторы ботов не подключаются. С площадками работает свой код |
| **Расписание ведёт сервер, компьютер оператора держит дубль** | компьютер спит и выключается. Дубль даёт копию, сторожа и аварийный перехват руками. Перехват начинается, только когда известно, что сервер не выпускает: выпускающий всегда один |
| **Instagram и Threads месяц работают через приложение Meta исполнителя**, потом переезжают на приложение клиента | у клиента пока нет учётной записи разработчика. Остальные площадки с первого дня на аккаунтах клиента |
| **Свой счётчик переходов** | счётчиками сайта занимаются другие подрядчики, доступа может не быть. Каждая ссылка идёт через `/go/…` с меткой площадки |
| **Персональные данные не покидают сервер** | на компьютер оператора и в витрину уходит только счёт |
| **То, что люди пишут в бот, программы не читают** | сессии Codex работают на серверах за границей. Текст вопросов из бота остаётся на сервере компании, в снимок идёт только их число. Публичные комментарии идут без автора и с вычищенными телефонами. Обе границы двигает только клиент: `zavod.config.json`, блок `privacy` |
| **Витрина Obsidian — итог внедрения** | собирается программой из живого состояния завода, а не пишется руками |

Подробно, со схемами: `docs/02-АРХИТЕКТУРА.md`.

## 6. Как устроена работа в Codex

Одна сессия — один тред Codex с рабочим каталогом проекта. У каждой свой промпт и своя граница.

| Сессия | За что отвечает | Промпт |
|---|---|---|
| **S0. Фундамент** | серверы, релей, ключи, дубль, выкладка, код | `prompts/sessions/S0-ФУНДАМЕНТ.md` |
| **S1. Массовые каналы** | Threads, Telegram, ВКонтакте, Дзен | `prompts/sessions/S1-МАССОВЫЕ-КАНАЛЫ.md` |
| **S2. Видео** | YouTube, Instagram, Rutube, видео ВКонтакте | `prompts/sessions/S2-ВИДЕО.md` |
| **S3. Бот и заявки** | кодовые слова, материалы, формы, воронка | `prompts/sessions/S3-БОТ-И-ЗАЯВКИ.md` |
| **S4. Тренды и новости** | банк тем, сборщик новостей, находки | `prompts/sessions/S4-ТРЕНДЫ-И-НОВОСТИ.md` |
| **S5. Цифры и разбор** | недельный разбор, что меняем | `prompts/sessions/S5-ЦИФРЫ-И-РАЗБОР.md` |
| **S6. Комментарии** | черновики ответов на вопросы людей | `prompts/sessions/S6-КОММЕНТАРИИ.md` |
| **S7. Витрина** | хранилище Obsidian | `prompts/sessions/S7-ВИТРИНА-OBSIDIAN.md` |

**Как открыть сессию.** Новый тред в Codex, каталог проекта, первое сообщение:

```text
Сессия S1.
```

Codex подгрузит навык сессии из `.agents/skills/`, а тот отправит к промпту. Если навык не сработал, первое сообщение такое:

```text
Прочитай prompts/sessions/S1-МАССОВЫЕ-КАНАЛЫ.md и работай по нему.
```

Задание на конкретную вещь даётся по образцу `prompts/samples/задание-исполнителю.md`.

**Правила для всех сессий.**

- Сессия делает своё и не заходит в чужое. Сессия текстов не правит код, сессия видео не трогает бота.
- Одно задание — одна вещь. Десять текстов за заход сходятся на одном шаблоне.
- Тексты пишет старшая модель с высоким усилием рассуждения. Младшей остаются разбор лент и сводки: ветки, написанные младшей моделью, у нас читались как конвейер.
- Сессия не публикует. Она ставит запись в очередь и отправляет на согласование.
- Сессия не пишет в рабочую группу. Сообщение людям клиента она готовит, отправляет его оператор.
- Сессия не видит ключей и данных людей. То, что ей нужно, есть в снимке счётом.
- В конце сессии короткий отчёт: что сделано, что на согласовании, что нужно от клиента.

**В каком порядке запускать.** S0 первой: без ключей и связи остальным не на чем работать. Затем S4 (разбор статей в банк тем) и S2 (серии на существующих роликах канала) параллельно: первая часть их работы идёт по файлам проекта, без сервера и ключей, и в первом сообщении треда это нужно сказать (`docs/00-С-ЧЕГО-НАЧАТЬ.md`, раздел 6). S1 с первого дня, когда заработал хотя бы один канал. S3 готовит материалы сразу, а приём открывается после утверждения согласий клиентом. S5 и S6 с третьей недели. S7 в конце месяца.

## 7. Путь одного материала

```text
тема из банка → текст по образцу → проверка фактов → файл записи
  → npm run check            пять проверок: готовность, речь, реклама, факты, ролик
  → npm run queue -- add     запись встаёт в ближайший слот рабочей сетки площадки
  → npm run queue -- submit  карточка в рабочей группе
  → «Одобрить» │ «Правка» │ «Снять»   нажимает человек клиента
  → слот: сервер выпускает, перед выпуском ещё раз проверяет готовность и рекламу
  → журнал: «вышло» только с номером публикации от площадки;
    у ручной выкладки сначала «передано», а «вышло» по кнопке «Выложено»
  → цифры раз в сутки → недельный отчёт → решения → банк тем
```

Одна запись очереди — один материал на одной площадке в один слот. Статья, разошедшаяся веткой, постом и роликом, даёт три записи с общим полем `material`.

Образцы на каждый вид работы и готовые записи: `prompts/samples/README.md`.

## 8. Путь заявки

```text
публикация ─► кодовое слово в Instagram ─► ссылка в директ ─┐
           ─► ссылка в бота с меткой площадки ──────────────┤
           ─► ссылка /go/… на статью сайта                  ▼
     бот: материал сразу ─► «Обсудить мой объект» ─► согласие отдельным сообщением
        ─► заявка записана на сервере в России ─► карточка в группе ─► «Взял в работу»
```

Кодовых слов на старте два: **ПРИЁМКА** (чек-лист приёмки покрытия, для заказчика) и **РАСХОД** (расчёт крошки и связующего, для укладчика). Третье, ТОЛЩИНА, выключено, пока клиент не снял противоречие в цифрах сайта. Слова работают только в Instagram; остальным площадкам тот же материал отдаёт ссылка в бота.

Бот, формы и кодовые слова закрыты в коде, пока юрист клиента не утвердил тексты согласий, а компания не подтвердила уведомления в Роскомнадзор. Это не поломка: `src/leads/legal.mjs`. Пока приём закрыт, публикации ведут на статьи сайта: запись с кодовым словом, ссылкой в бота или на форму проверка не пропустит.

## 10. Что не проверено боем

Говорится клиенту на первой встрече и сессиям в их промптах.

| Что | Чем подстраховано |
|---|---|
| Публикация рилса своим кодом | первый рилс идёт под присмотром оператора |
| Загрузка на Rutube по ключу | с первого дня ручной пакет |
| Фото и видео во ВКонтакте по ключу администратора | ручной пакет; права запрашиваются у поддержки |
| События о комментариях Instagram для аккаунта-тестировщика | опрос раз в пять минут |
| Кодовое слово в директе в первый месяц | ждёт правки пересылки на стороне исполнителя: `docs/patches/kormishin-site-ig-forward.md` |
| Threads через приложение исполнителя | в прошлом запуске не заработал: слоты уходят Telegram и ВКонтакте |
| Первая загрузка на YouTube из нового проекта Google | ролик может остаться закрытым: открывается руками, проект подаётся на проверку |
| Снятие и перестановка срока выхода ролика на YouTube | написано по документации Google. Проба стоит в сессии S0; после каждой правки сервер перечитывает ролик и о неудаче пишет в группу с действием для человека |
| Сверка «вышел ли пост» в Telegram-канале после оборванной отправки | идёт по веб-витрине канала; с сервера в России она может не открыться, тогда запись не повторяется, а решение отдаётся человеку |
| Перехват и возврат расписания | проверены тестами на двух каталогах данных в одном процессе, на живой паре «сервер и компьютер» не пройдены. Первый перехват делается учебным, в день без одобренных записей: `docs/06-РАСПИСАНИЕ-И-ДУБЛЬ.md`, разделы 6 и 7 |
| Восстановление сервера из архива и сверка с копией расписания | проверены тестами; отметка в архиве проверена на GNU tar, на сервере клиента архив ни разу не разворачивался. Первая квартальная проверка архива делается до запуска публикаций: `ops/СЕРВЕР.md`, разделы 9 и 11 |
| Сертификаты на серверах | порядок «сначала сертификат, потом настройки» написан по документации certbot, на живом сервере этого клиента не пройден |
| Забирает ли Meta файлы из выбранного хранилища | запасное хранилище названо в `docs/04-ДОСТУПЫ-ПО-ПЛОЩАДКАМ.md` |

Полный список рисков с тем, что делаем по каждому: `docs/08-РИСКИ.md`. На чём мы уже обжигались: `docs/05-ГРАБЛИ.md`.
