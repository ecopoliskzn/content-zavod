# Образец: задание сессии

Оператор даёт сессии одно задание за раз. Задание пишется по этому образцу: одним сообщением в начале сессии либо файлом `content/tasks/<дата>/<имя>.json`, если задание нужно сохранить.

## Зачем форма

Сессия знает только то, что ей сказали и что лежит в проекте. Задание «напиши ветку про приёмку» даёт ветку «вообще про приёмку»: гладкую и ни о чём. Задание по форме отвечает на вопросы, которые сессия иначе решит за оператора и решит не так: для кого, из чего, что уже выходило, чего нельзя.

Два поля делают половину дела: **почему** и **не делать**. Без первого текст получается про хорошее вообще. Без второго сессия добросовестно сделает лишнее.

## Форма

```json
{
  "сессия": "S1",
  "что": "ветка Threads",
  "тема": "Почему мокрое покрытие не принимают",
  "читатель": "заказчик площадки: управляющая компания, школа, детский сад",
  "материал": "blog:kak-proverit-kachestvo-rezinovogo-pokrytiya-posle-ukladki-chek-list-dlya-zakazchika-chast-2",
  "источник": [
    "content/articles/<слаг>.md, раздел «Почему нельзя принимать мокрое покрытие»",
    "тот же вопрос в части 1, раздел «Когда проводить приёмку»"
  ],
  "образец": "prompts/samples/статья-в-ветку.md",
  "почему": "Сезон кончается, объекты сдают под дождём. В комментариях под роликом о приёмке дважды спросили, можно ли принимать после дождя. Прошлые ветки начинались с цифры: эта начинается с того, что именно вода прячет.",
  "якорь": "шесть вещей, которых не видно на мокром покрытии",
  "ссылка": "priemka2",
  "выход": "content/queue/threads/<дата>/mokroe-ne-prinimayut.json",
  "проверки": [
    "npm run check -- --file=<выход>: ни одной строки с ⛔; каждое замечание ⚠ исправлено либо названо в отчёте с причиной",
    "текст нигде не говорит сильнее источника: prompts/samples/фактчек.md, раздел «Сильнее источника»",
    "каждая цифра и каждое «потому что» есть в источнике: prompts/samples/фактчек.md",
    "начало не повторяет ветки из mirror/РАСПИСАНИЕ.md за шестьдесят дней"
  ],
  "не_делать": [
    "не ставить в очередь и не отправлять на согласование: только файл записи и отчёт",
    "не писать про швы и толщину: это отдельные темы банка",
    "не объяснять, почему вода скрывает дефект, если этого нет в статье",
    "не брать вторую тему, даже если осталось время"
  ]
}
```

| Поле | Что писать |
|---|---|
| `сессия` | какая сессия делает: S1–S7 |
| `что` | один предмет: ветка, пост, сценарий, запись ролика, разбор недели |
| `тема` | строка из банка тем, а не предмет вообще |
| `читатель` | один из четырёх: заказчик, укладчик, частник, тот, кто ищет дело |
| `материал` | обозначение для записи очереди: `blog:…`, `news:…`, `case:…`, `interview:…` |
| `источник` | файлы и разделы, а не «статья клиента» |
| `образец` | по какому образцу писать |
| `почему` | что случилось, из-за чего тема берётся сейчас, и чем она должна отличаться от прошлых |
| `якорь` | с чего начинается текст, если оператор это уже знает |
| `ссылка` | слаг из `bot/links.json` либо ключ материала бота |
| `выход` | куда положить результат |
| `проверки` | что должно быть верно перед сдачей |
| `не_делать` | границы: чего не трогать и где остановиться |

Поля, которых оператор не знает, пропускаются. Поля `почему`, `выход` и `не_делать` не пропускаются никогда.

## Одно задание — одна вещь

Десять текстов за один заход сходятся на одном шаблоне. У нас так и вышло: десять текстов, написанных параллельно по одному заданию, получили одинаковые зачины и одинаковые концовки (`docs/05-ГРАБЛИ.md`, раздел «Тексты»).

Поэтому:

- одна ветка за задание;
- одна площадка за задание: ветка и пост по той же теме пишутся двумя заданиями и в разное время;
- между двумя текстами одной площадки сессия читает, чем начинался предыдущий.

## Что сессия возвращает

Короткий отчёт в конце работы. Не пересказ того, что сделано, а то, что оператору нужно знать.

```text
Сделано: content/queue/threads/2026-10-15/mokroe-ne-prinimayut.json
Проверки: пройдены, замечаний нет.
Факты: 6, все из статьи о приёмке, часть 2.
Сомнение: в статье «следы инструмента» названы среди того, что прячет вода, но не сказано почему. В тексте оставил без причины.
Вопрос утверждающему (поле ask): нет.
Не сделано: —
В банк тем: «как проверить водоотвод ведром воды», из того же раздела.
```

Если задание выполнить нельзя, сессия не подгоняет результат, а пишет, чего не хватило: нет источника для цифры, тема закрыта списком противоречий, в статье нет нужного раздела.

## Когда сессия останавливается и спрашивает

- в источнике нет того, что требует задание;
- для текста нужна цифра из списка противоречий;
- задание требует назвать заказчика, цену или конкурента;
- проверка останавливает запись, и снять претензию можно только изменив смысл;
- задание выходит за границы сессии: сессия S1 не правит код, сессия S2 не трогает бота.

Во всех остальных случаях сессия доводит задание до конца сама и не спрашивает разрешения на каждый шаг.

## Чего в задании не бывает

- «Сделай хорошо» и «в нашем стиле»: стиль записан в `docs/07-РЕДПОЛИТИКА.md`.
- Двух предметов через «и».
- Срока «срочно»: срочное не отменяет согласования.
- Готового текста с просьбой «улучшить»: исправляется конкретное, по замечанию утверждающего (`npm run queue -- inbox`).
