# Образец: серии, плейлисты и старые ролики канала

Сессия S2. Реестр серий: `content/youtube/series.json`. Опись канала: `content/youtube/channel.json`.

## Зачем серии

Короткий ролик зритель досматривает и уходит: конечных заставок и подсказок у коротких роликов нет. Дальше его ведут три вещи: плейлист серии, ссылки на соседние ролики в описании и закреплённый комментарий.

На канале клиента 243 ролика, и они не связаны ничем. Трёхчастная история про электровал не ведёт из части в часть. Это работа, которая делается без единого нового кадра, поэтому с неё начинается первая неделя.

## Два вида серий

| Вид | Поле `order` | Что это | Порядок |
|---|---|---|---|
| Тематическая | `views` | самостоятельные ролики об одном | первым стоит самый просматриваемый: плейлист открывают с первого ролика, и он уже доказал, что его смотрят |
| По частям | `parts` | одна история в нескольких роликах | как в реестре: порядок задаёт сюжет. В описаниях «Следующая часть» и «Предыдущая часть» |

## Сначала согласие клиента

Плейлист и блок ссылок под старыми роликами меняют канал клиента. Поэтому до первой команды утверждающий получает список одним сообщением: какие серии, какие ролики в каждой, как будет выглядеть блок ссылок под роликом. Сообщение готовит сессия, в рабочую группу его отправляет оператор. Работа начинается после «да» утверждающего. Согласие нужно один раз на состав серий; новые ролики попадают в серии уже через обычную карточку.

## Порядок работы с серией

**1. Плейлист и ссылки.**

```bash
npm run yt -- --series-create --series=leonardo
```

Команда создаёт плейлист на канале, складывает в него ролики серии, записывает номер плейлиста в реестр и ставит под описанием каждого ролика серии блок ссылок: плейлист, соседние части либо два «смотрите также».

У старых роликов канала меняется только то, что завод дописал сам. Текст описания, написанный клиентом, команда не трогает: блок ссылок дописывается в конец, а при следующем запуске убирается ровно тот блок, который был поставлен в прошлый раз. Строку «Смотрите также: …», которую клиент когда-то написал сам, команда своей не считает.

Что хранится рядом. В каталоге `content/youtube/history/` по файлу на ролик: каким описание было до первой правки завода и какой блок дописан последним. Каталог коммитится вместе с реестром. Вернуть ролику прежнее описание:

```bash
npm run yt -- --restore --video=<номер ролика>
```

Если описание после нашей правки меняли руками в Студии и блок оказался не на месте, команда этот ролик пропускает и говорит об этом: посмотри его в Студии сам.

**2. Порядок по просмотрам** (для тематических).

```bash
npm run yt -- --series-sort --series=leonardo
```

**3. Обновить ссылки**, когда в серии появился новый ролик или изменился порядок.

```bash
npm run yt -- --relink --series=leonardo
```

**4. Добавить в серию старый ролик канала.**

```bash
npm run yt -- --series-add --series=proraby --video=<номер ролика>
```

**5. Новый ролик** попадает в серию сам, если в записи очереди стоит поле `series`.

После шагов 1–3 реестр изменился: файл `content/youtube/series.json` коммитится.

## Закреплённые комментарии под старыми роликами

Под десятью самыми просматриваемыми роликами канала ставится комментарий со ссылкой. Программа закрепить его не может: текст и ссылки собираются списком и уходят сотруднику клиента одним сообщением.

Какие ролики и куда предлагаем вести:

| Ролик | Просмотры | Куда ведёт ссылка |
|---|---:|---|
| Набор «Леонардо» (две версии) | 84 255 и 68 752 | каталог сайта: слаг `katalog` |
| Прораб Олег и щука | 37 850 | плейлист серии «Прорабы „Экополиса“» |
| Электровал, часть 3 | 32 253 | плейлист серии про электровал |
| Покрытие, уложенное в ноябре при −13 | 9 259 | плейлист серии о проверке временем |

Ссылка на страницу сайта идёт через счётчик: `npm run link -- --slug=katalog --channel=youtube --name=<короткое имя>`. Нужной страницы нет среди коротких ссылок: она добавляется в `bot/links.json`, коммитится и выкладывается на сервер.

Ролик про укладку при −13 на статью о температуре не ведём: температура укладки стоит в списке противоречий сайта (`docs/09-ФАКТУРА-КЛИЕНТА.md`, раздел 7).

## Новые названия старым роликам

У 129 роликов название начинается с «#shorts», у большинства оно называет предмет. Переименование двадцати лучших роликов может дать им вторую жизнь, но это правка канала клиента, и делается она только после его «да».

Порядок:

1. Взять двадцать роликов с наибольшим числом просмотров из `content/youtube/channel.json`.
2. Узнать, что в каждом ролике. Сам ролик сессия не видит и не слышит. Список двадцати роликов со ссылками уходит оператору; он возвращает по каждому две строки: что происходит в кадре и что сказано. Можно иначе: оператор снимает расшифровку речи своим конвейером и кладёт её в проект.
3. К каждому предложить новое название по правилам: событие вместо темы, до 80 знаков, без «#shorts». Только по строкам оператора либо расшифровке: название, придуманное по старому названию, получается выдумкой, а стоять оно будет на канале клиента от его имени.
4. Собрать таблицу «было → стало → почему» файлом. Утверждающему её отправляет оператор.
5. После «да» название старого ролика меняется в Студии руками: программа правит названия только у роликов, загруженных через завод (`npm run yt -- --update --id=<запись>`).

Образец строк такой таблицы. Названия «стало» здесь показывают приём; настоящие пишутся после просмотра каждого ролика.

| Было | Стало | Почему |
|---|---|---|
| #shorts Наш прораб Олег | название по тому, что Олег делает или говорит в ролике | было имя, станет событие |
| #shorts Разметочная машинка | что машинка делает за минуту и вместо чего | было слово из каталога |
| Проверили покрытие, уложенное в ноябре при −13 | оставить | событие, цифра и интрига уже есть: ролик обогнал обычный в 16 раз |

## Повторы на канале

История про щуку выложена четыре раза: 37 850, 2 961, 2 707 и 2 378 просмотров. Повторы отбирают показы у первого ролика. Что с ними делать, решает клиент; предложение такое: три повтора перевести в «доступ по ссылке», первый оставить. Удалять не нужно: вместе с роликом пропадают его просмотры и комментарии.

## Раз в месяц

```bash
npm run yt -- --channel --analytics
```

Команда пересобирает опись канала: просмотры, досмотр, подписки с ролика, отрыв от обычного. По ней:

- пересортировать тематические серии: `--series-sort`;
- найти ролик, который обогнал обычный в пять раз и больше, и снять продолжение;
- найти серию, в которой три ролика подряд ниже обычного, и остановить её.

## Чего не делаем

- Не меняем название и описание старого ролика без согласованного списка.
- Не удаляем ролики.
- Не ставим в описания кодовое слово.
- Не собираем серию из одного ролика: плейлист из одного ролика никуда не ведёт.
