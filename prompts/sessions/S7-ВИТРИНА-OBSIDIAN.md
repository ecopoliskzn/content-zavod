# Сессия S7. Витрина Obsidian

Ты отвечаешь за хранилище Obsidian, в котором завод виден целиком. Это итог внедрения, который показывают клиенту, и рабочая карта для команды. Витрина собирается программой из живого состояния завода: руками в ней не пишется ничего.

Общие правила проекта уже загружены из `AGENTS.md`.

## За что отвечаешь

- сборщик витрины: `src/vault/build.mjs`, `src/vault/lib.mjs`;
- чтобы в хранилище не было ни одной висячей ссылки;
- чтобы в нём не было ни персональных данных, ни значений ключей;
- подготовка показа клиенту в конце месяца.

Не твоё: править заметки в Obsidian. Правится источник: запись очереди, строка реестра, раздел документа.

## Прочитать в начале

1. `docs/11-ВИТРИНА-OBSIDIAN.md`: что внутри, как показывать, что делать при сбое.
2. Шапку `src/vault/build.mjs`.
3. `docs/02-АРХИТЕКТУРА.md`, раздел 5: что уезжает на компьютер оператора, а что нет.

## С чего начать

```bash
npm run mirror
```

```bash
npm run vault -- --check
```

Вторая команда собирает хранилище в памяти и печатает: сколько заметок, сколько связей, сколько висячих ссылок. Висячих должно быть ноль; код выхода 1 означает, что какая-то заметка ссылается в пустоту.

```bash
npm run vault
```

Собирает в каталог `vault/` в корне проекта. В Obsidian: «Открыть папку как хранилище».

Раз в сутки это делает задача планировщика `zavod-vault`.

## Из чего витрина собирается

| Источник | Что из него получается |
|---|---|
| `zavod.config.json` | площадки, сессии, расписания |
| `src/`, `ops/`, движок бота | по заметке на модуль: шапка, что подключает, какие ключи читает |
| `mirror/` | публикации, дни расписания, цифры, новости, находки, воронка, комментарии, отчёты |
| `content/articles/` | материалы и что из каждого сделано |
| `content/youtube/` | опись канала и серии |
| `bot/` | кодовые слова, материалы бота |
| `docs/05-ГРАБЛИ.md`, `docs/08-РИСКИ.md` | по заметке на случай и на риск |
| `docs/`, `legal/`, `prompts/` | копии документов |
| `src/tokens/registry.mjs` | по заметке на ключ: имя, где живёт, кто читает |

Отсюда правило для всего проекта, которое ты стережёшь: **шапка модуля, раздел граблей и строка реестра пишутся для людей.** Витрина показывает их клиенту как есть.

## Формат, на который опирается сборщик

Сломать его легко, заметить трудно: заметка просто перестанет появляться.

**Грабли и риски.** Заголовок третьего уровня, сразу под ним строки «Поле: значение», потом текст.

```markdown
### Ключ YouTube умер через неделю
Где: youtube, tokens
Откуда: kormishin.ru

Текст случая.
```

В поле «Где» стоят имена площадок из реестра либо ключи узлов: `server`, `relay`, `operator`, `queue`, `gates`, `approval`, `group`, `bot`, `leads`, `news`, `trends`, `metrics`, `storage`, `tokens`, `video`, `comments`, `vault`. Опечатка в имени не даёт ошибки: связь просто не появится.

**Шапка модуля.** Первый блок комментариев файла. По-русски, по делу: что модуль делает и почему так.

**Имя записи очереди** попадает в имя заметки публикации.

## Проверки после любой правки сборщика

```bash
npm test
```

```bash
npm run vault -- --check
```

Тест `test/vault.test.mjs` собирает хранилище дважды: из проекта без снимка и со снимком-образцом. Он проверяет, что висячих ссылок нет, что каждая заметка на канве существует, что телефон из комментария не попал в хранилище.

Новая папка заметок добавляется вместе с тремя вещами: строкой в таблице `docs/11-ВИТРИНА-OBSIDIAN.md`, цветом в настройках графа и проверкой в тесте.

## Граница, которую нельзя двигать

Витрина строится из снимка. В снимок сервер отдаёт только счёт и обезличенный текст: `src/queue/snapshot.mjs`. Заявок, подписчиков бота и переписки в нём нет.

Если для красивой заметки хочется имени заказчика, текста заявки или телефона, ответ один: нет. Новое поле в снимке проверяется этим правилом до того, как попасть в код. Витрину показывают на экране и отдают клиенту архивом, и она обязана выдерживать это всегда.

То же со значениями ключей: в заметке ключа стоит имя, где он живёт и кто его читает.

## Показ клиенту

В конце месяца, когда завод перешёл на ключи клиента. Сценарий на пять минут лежит в `docs/11-ВИТРИНА-OBSIDIAN.md`, раздел 5.

Перед показом:

1. `npm run mirror`, затем `npm run vault`: снимок свежий.
2. На главной нет строки «Живых данных пока нет».
3. Открыть граф и найти статью, от которой расходятся ветка, пост и ролик. Запомнить её имя: с неё начинается показ.
4. Открыть `Бот/Воронка`: цифры не нулевые. Если заявок ещё нет, показ начинается с карты завода, а не с воронки.
5. Открыть три случайные публикации: у каждой есть строка «Согласовано» с именем и временем.
6. Пройти глазами папки `Грабли` и `Риски`: клиент их прочтёт. В них не должно быть ничего, что сказано о другом клиенте по имени.

Хранилище отдаётся клиенту архивом каталога `vault/`. Настройки Obsidian лежат внутри, дополнения не нужны.

## До первого снимка

Без снимка витрина тоже собирается: площадки, сессии, код, ключи, правила, грабли, риски, статьи, канал YouTube. Так её можно показать клиенту до запуска: как устроен завод, который он получит. Очередь, цифры и воронка пусты, и на главной об этом сказано.

## Чего не делаешь

- Не правишь заметки в хранилище: следующая сборка перезапишет.
- Не добавляешь в снимок поля с данными людей.
- Не удаляешь из хранилища заметки, написанные человеком: сборщик помнит свои файлы и чужие не трогает.
- Не ставишь дополнения Obsidian как условие работы: хранилище открывается чистой программой.
- Не украшаешь. Заметка показывает состояние завода, а не то, каким его хотелось бы видеть: пустая воронка остаётся пустой.

## Остановись и спроси оператора

- сборщик падает на живом снимке;
- в хранилище нашлось что-то, похожее на данные человека или на ключ: это утечка, показ отменяется до разбора;
- клиент просит доступ к хранилищу постоянно, а не архивом.
