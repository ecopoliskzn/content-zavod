# Сессия S0. Фундамент

Ты поднимаешь завод: серверы, релей, бот-пульт, ключи площадок, дубль расписания. Текстов и роликов в этой сессии нет. Она заканчивается, когда по каждой площадке прошла одна тестовая запись полным путём.

Общие правила проекта уже загружены из `AGENTS.md`. Здесь только то, что касается этой сессии.

## За что отвечаешь

- серверы и релей: `ops/СЕРВЕР.md`;
- ключи площадок и их перенос: `docs/04-ДОСТУПЫ-ПО-ПЛОЩАДКАМ.md`, `docs/03-META-ЧЕРЕЗ-ПРИЛОЖЕНИЕ-ИСПОЛНИТЕЛЯ.md`;
- дубль расписания и сторож на компьютере оператора: `docs/06-РАСПИСАНИЕ-И-ДУБЛЬ.md`, `ops/windows/README.md`;
- выкладка кода, резервные копии, сроки ключей;
- код завода: правки, тесты, разбор сбоев;
- переезд на собственное приложение Meta клиента в конце месяца.

Не твоё: тексты, сценарии, ответы людям, решения о том, что публиковать.

## Порядок первой недели

Строго по порядку: следующий шаг начинается, когда предыдущий проверен действием.

| № | Шаг | Готово, когда |
|---|---|---|
| 1 | Два сервера, домен, хранилище | `https://<адрес завода>/health` отвечает `{"ok":true` |
| 2 | Случайные секреты на сервере | `node src/tokens/check.mjs --init` назвал созданные имена |
| 3 | Релей на втором сервере | `https://<адрес релея>/health` отвечает |
| 4 | Бот и рабочая группа с темами | `/help` в группе отвечает списком команд |
| 5 | Ключ оператора на компьютере | `npm run tokens -- --compare`: копии совпадают |
| 6 | Расписание на сервере, под пользователем `zavod` | `crontab -l` показывает задачи; `/health` показывает свежее время в поле `runnerAt` |
| 7 | Дубль и сторож | `npm run mirror` снял копию; задачи планировщика стоят |
| 8 | Telegram-канал | тестовая запись прошла путь до ссылки в журнале |
| 9 | YouTube | доктор назвал канал клиента; `npm run yt -- --channel` пересобрал опись; проба со сроком выхода пройдена (раздел ниже) |
| 10 | Threads | тестовая ветка из двух реплик вышла |
| 11 | Instagram | маркер живой, тип аккаунта профессиональный, тестовый рилс вышел |
| 12 | ВКонтакте | текстовая запись вышла ключом сообщества |
| 13 | Дзен, Rutube | связка канала с Дзеном работает; пакет Rutube пришёл в тему «Выложить руками», после кнопки «Выложено» запись стала «вышло» |
| 14 | Резервная копия | `ops/backup.sh` отработал руками; архив есть в приватном бакете |

Расписание стоит шестым, раньше площадок: тестовую запись выпускает проход по расписанию, без него она останется «одобрено, ждёт слота» навсегда. Журнал `/var/log/zavod/release.log` после установки расписания пуст, и это не поломка: проход, которому нечего выпускать, в журнал не пишется. Живость видна в `/health`.

Шаги 8–13 можно менять местами: площадка подключается, когда её владелец на связи.

Каждая команда на сервере идёт под тем пользователем, который назван в `ops/СЕРВЕР.md` над блоком. Команда завода, запущенная под `root`, откажется работать: файлы, созданные ею, завод потом не прочитает.

## Тестовая запись

Каждая площадка проверяется одной записью, которая проходит весь путь. Чтение настроек проверкой не считается.

1. Взять образец: `prompts/samples/entries/<площадка>-….json`, скопировать в `content/queue/<площадка>/<дата>/proba-<площадка>.json`, поменять имя записи.
2. Убрать из копии всё, что зовёт в бота: поле `botKey`, ссылки вида `t.me/…?start=…`, строку с кодовым словом. В первую неделю приём заявок закрыт (согласия ещё не утверждены), и проверка готовности такую запись не пропустит. Это правильный отказ, а не поломка.
3. Для ролика (YouTube, Instagram, Rutube) нужен настоящий файл: короткий вертикальный ролик, который клиент разрешил взять для пробы. `npm run media -- --file=<путь>` на компьютере оператора, адрес из вывода ставится в поле `media`.
4. `npm run check -- --file=<файл>`
5. Поставить на сегодня, с запасом в сорок минут на согласование. Время указывается руками, потому что рабочая сетка может дать слот через несколько дней:

   ```bash
   npm run queue -- add --file=<файл> --date=<ГГГГ-ММ-ДД> --time=<ЧЧ:ММ>
   ```

   Строка «времени нет среди слотов площадки» при этом законна.
6. `npm run queue -- submit proba-<площадка> --channel=<площадка>`
7. Утверждающий нажимает «Одобрить» в рабочей группе до назначенного времени. Нажал позже: запись сама уйдёт в ближайший слот сетки, и её нужно вернуть на сегодня командой `npm run queue -- move proba-<площадка> --channel=<площадка> --date=<ГГГГ-ММ-ДД> --time=<ЧЧ:ММ>`.
8. Через пять–десять минут после назначенного времени: `npm run queue -- show proba-<площадка> --channel=<площадка> --history`. Статус «вышло», есть ссылка.
9. Открыть ссылку глазами.
10. Попросить владельца аккаунта удалить тестовую публикацию.

Тестовая запись публикуется на настоящей площадке клиента. Поэтому её текст осмысленный, а утверждающий заранее знает, что это проверка.

У площадок с ручной выкладкой (Дзен, Rutube без ключа) после назначенного времени запись становится «передано на ручную выкладку», а «вышло» ей ставит кнопка «Выложено» под пакетом. Проверяется и это.

## Проба YouTube: срок выхода и его снятие

Ролик на YouTube загружается закрытым с датой выхода, и открывает его сам YouTube. Поэтому у завода есть обязанность: если запись сняли либо отозвали согласие, срок с ролика должен исчезнуть. Этот механизм написан по документации Google и боем не проверен. Его проверяют здесь, на пробном ролике, до первой настоящей публикации.

1. Пробная запись YouTube поставлена на завтра и одобрена.
2. `npm run yt -- --upload --id=proba-youtube --file=<путь>`. В выводе: «доступ: private» и дата выхода.
3. В Студии YouTube у ролика стоит «Запланировано» на эту дату.
4. Утверждающий нажимает под карточкой «Отозвать согласие». Бот отвечает: «Срок выхода на YouTube снят: ролик остаётся закрытым».
5. В Студии у ролика больше нет даты, доступ «Ограниченный».
6. Утверждающий снова нажимает «Одобрить». Бот отвечает строкой со сроком, в Студии дата вернулась.
7. Команда `/stop_release` в группе: срок снова снят. `/start_release`: вернулся.
8. Проба закончена. Под одобренной карточкой кнопки «Снять» нет, поэтому утверждающий нажимает «Отозвать согласие», а затем «Снять» (либо оператор снимает запись сам: `npm run queue -- cancel proba-youtube --channel=youtube`). Бот отвечает, что срок снят и ролик остаётся закрытым. Владелец канала удаляет пробный ролик.

Если на шаге 4 или 7 бот ответил, что срок снять не удалось, либо в Студии дата осталась: это остановка. До починки ролики на YouTube загружаются **только после «Одобрить» и не раньше чем за час до слота**, а оператор знает, что «Снять» для загруженного ролика нужно дублировать руками в Студии. Запиши случай в `docs/05-ГРАБЛИ.md` и скажи оператору.

Вторая вещь, которую показывает эта же проба: не оставляет ли новый проект Google ролик закрытым насильно (`docs/08-РИСКИ.md`).

## Ключи

- Значение ключа не появляется в сессии никогда: ни в выводе, ни в файле проекта, ни в твоём ответе. Имя и отпечаток: `npm run tokens`.
- Файл окружения не открывается командами, которые печатают его содержимое. Что задано, показывает `npm run doctor`.
- Ключ переносится между машинами файлом: `--export`, `scp`, `--import`. Команда приёма не пустит ключ туда, где ему не место. Файл окружения целиком с машины на машину не копируется никогда: `npm run tokens -- --compare` называет расходящиеся ключи и пишет готовые команды для каждого направления.
- Пароли аккаунтов клиента не запрашиваются и не принимаются. Владелец входит сам, на своём устройстве.
- Если значение ключа всё-таки попало в вывод, это утечка: остановись, скажи оператору, ключ перевыпускается.

## Выкладка

```bash
bash ops/deploy.sh zavod@<адрес сервера>
```

- Вывод этой команды не пускается через пайп: пайп съедает код выхода, и провал выглядит успехом.
- Выкладывается только закоммиченное.
- Коммит: файлы перечисляются поимённо. `git add -A` и `git add .` не используются.
- После выкладки: `/health`, затем `npm run mirror`.
- Правка `ops/crontab.txt` ставится на сервере отдельной командой: выкладка расписание не меняет.

## Правка кода

- Сначала тест, который падает на ошибке, потом правка.
- У очереди один писатель: `src/queue/store.mjs`. Никакой другой модуль в файл очереди не пишет.
- Проверка, которая останавливает запись перед выпуском, добавляется только в группы «готовность» и «реклама». Новая проверка речи или фактов на выпуске однажды сняла шесть одобренных постов за день.
- Правило проверки добавляется вместе с примером текста, на котором оно сработало, и с тестом.
- Код с обратными косыми чертами (регулярные выражения) правится редактором файлов, а не скриптом в командной строке: оболочка их теряет молча.
- После правки: `npm test`, `npm run test:bot`, `npm run doctor`, `npm run vault -- --check`.

## Разбор сбоя

1. Что видит человек: тревога в группе, запись в статусе «ошибка», молчание.
2. Журнал: `npm run queue -- show <имя> --history`; на сервере `/var/log/zavod/<задача>.log`.
3. Код 1 или код 2. Код 1 означает отказ по правилу: чинить нечего, нужно ответить человеку. Код 2 означает поломку окружения.
4. Отказ площадки или сеть. «Не смог спросить» не значит «ключ мёртв»: тревога о ключе уходит только на отказ.
5. Починил: случай записывается в `docs/05-ГРАБЛИ.md` с полями «Где» и «Откуда».

## Остановись и спроси оператора

- действие необратимо: удаление данных, перевыпуск ключа, смена адреса обновлений бота;
- нужно что-то сделать в аккаунте или кабинете клиента;
- правка боевого проекта исполнителя (`docs/patches/kormishin-site-ig-forward.md`): только после «да» владельца;
- доктор зелёный, а тестовая запись не выходит;
- хочется обойти расписание, согласование или проверку «один раз, для проверки».

## Сделано

Сессию можно закрывать, когда:

- `npm run doctor -- --live` на сервере и `npm run doctor -- --live --media` на компьютере оператора без красных строк, каждая жёлтая объяснена. Хранилище роликов проверяется с компьютера: его ключи на сервере не лежат. Жёлтые строки о неутверждённых согласиях на этом шаге законны: приём заявок открывает клиент, не ты;
- по каждой подключённой площадке есть вышедшая тестовая запись;
- проба YouTube со сроком выхода пройдена либо её отказ записан и известен оператору;
- дубль снимается, сторож шлёт тревогу при остановленном сервисе. Проверяется до запуска, пока публикаций нет: сервис остановлен, `npm run mirror -- --watch` прислал тревогу в группу, сервис запущен;
- учебный перехват расписания пройден либо его отказ записан и известен оператору: `docs/06-РАСПИСАНИЕ-И-ДУБЛЬ.md`, раздел 7, «Учебный перехват»;
- резервная копия лежит в двух местах;
- оператору отдан список: что подключено, что ждёт клиента, что не проверено боем.
