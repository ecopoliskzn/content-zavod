# S0: как восстановить проверку комментариев всех площадок

05.11.2026. Основание: свежий серверный проход в s0-live-comments-check.md и чтение src/comments/collect.mjs. Повторный сбор не запускался. В этом плане нет обещания полного охвата: сегодняшние нулевые результаты его не подтверждают.

## Сначала исправить достоверность отчёта

Отдельно учитывать на каждой площадке: время попытки, время последнего полного успешного чтения, число найденных целей, запрошенных целей, страниц, веток/ответов, пропусков и ошибок. Пустой журнал целей означает «нет целей для проверки», а не «комментариев нет». Частично прочитанные данные сохранять с явным неполным охватом; ошибка следующей страницы не должна исчезать за успешной первой страницей. Общий lastSuccessAt не должен изображать все площадки проверенными после одного пустого прохода.

До изменения кода нужны падающие тесты: ноль целей; отказ одной из целей; отказ второй страницы; API error внутри HTTP 200; несколько страниц комментариев и вложенных ответов; повторный сбор без дублей. Синтетические ответы не содержат реальных людей. Затем штатные тесты и отдельная выкладка. Тексты и авторы остаются только на российском сервере, наружу — агрегаты.

## Площадки

| Площадка | Следующее конкретное действие | Что считать проверкой |
|---|---|---|

| VK | Отдельным серверным чтением проверить допустимость wall.getComments с уже имеющимся group token и реальным публичным постом сообщества; результат только код/счётчики. Не заменять ключ в коде наугад. | Проверены права именно этого метода; определён собственный путь описи публичных постов, пагинации и вложенных ответов. Сейчас 21-дневный журнал завода пуст и архив не охватывает. |
| Rutube | Согласовать опись публичных видео клиента, включая выпущенные до завода. В текущем SOURCES такого адаптера нет; настройки группы и privacy этим планом не меняются. |
| Дзен | Проверить официальный доступный клиенту путь комментариев. Не подменять его скрейпингом закрытого кабинета или внешним сервисом. |

Новый сбор после исправлений — под общим /tmp/zavod-comments.lock, без --send, с соблюдением частоты. S6 получает тексты только штатной queue comments. Этот документ не меняет cron, privacy, ключи, код сборщика и состояние публикаций.
