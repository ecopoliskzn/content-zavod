# Задачи на компьютере оператора

Три задачи планировщика Windows. Ставятся одной командой из корня проекта:

```bash
powershell -ExecutionPolicy Bypass -File ops\windows\install-tasks.ps1
```

| Задача | Когда | Что делает |
|---|---|---|
| `zavod-mirror` | каждые 15 минут | снимает копию очереди и журналов с сервера в `mirror/`, обновляет `mirror/РАСПИСАНИЕ.md`; если сервер молчит, шлёт тревогу в рабочую группу |
| `zavod-vault` | каждый день в 08:15 | пересобирает витрину Obsidian по свежей копии |
| `zavod-takeover` | каждые 5 минут, **выключена** | аварийный выпуск с компьютера. Включается только после перехвата расписания |

Журналы: `mirror\mirror.log`, `mirror\vault.log`, `mirror\takeover.log`.

## Что нужно знать

**Что сторожу нужно в `.env.local`.** Адрес сервера и ключ оператора (`QUEUE_API_BASE`, `ADMIN_API_TOKEN`), адрес и секрет релея (`TG_RELAY_URL`, `TG_RELAY_SECRET`), номер рабочей группы (`TG_GROUP_ID`) и номер темы «Тревоги» (`TG_TOPIC_ALERTS`). Без последнего тревога о молчащем сервере уйдёт в общую тему группы, где её не ждут. Доктор на компьютере оператора скажет, чего не хватает: `npm run doctor`.

**Сервер главный, компьютер запасной.** Пока компьютер спит, его задачи не идут: копия стареет, сторож молчит. Расписание от этого не страдает, выпуск ведёт сервер. Проверьте в настройках электропитания, что компьютер не засыпает в рабочие часы, иначе тревога о молчащем сервере придёт с опозданием.

**Обёртки `.cmd` создаёт установщик.** В них зашит полный путь к `node.exe`: планировщик запускает задачи со своим `PATH`, и голое `node` там молча не находится. Переставили Node или перенесли проект в другую папку — запустите установщик ещё раз.

**Файлы `.cmd` и `.ps1` только латиницей.** Планировщик читает `.cmd` в кодировке OEM, PowerShell 5.1 читает `.ps1` без метки в ANSI. Кириллица в них превращается в мусор, и задача падает без внятной ошибки. У нас так однажды не вышли девять публикаций подряд.

## Перехват расписания

Порядок действий лежит в `docs/06-РАСПИСАНИЕ-И-ДУБЛЬ.md`, разделы 6 и 7. Коротко:

```bash
npm run mirror -- --takeover --yes
```

Перехват начинается, только когда известно, что сервер не выпускает. Сервер ответил: команда сама его остановит и снимет свежую копию. Сервер не ответил: команда откажет и напишет, как остановить выпуск на нём (по SSH либо выключением в панели Timeweb). После этого:

```bash
npm run mirror -- --takeover --yes --server-stopped
```

При молчащем сервере команда назовёт записи, чей слот наступил до перехвата: их она сама не выпустит, каждую нужно посмотреть на площадке глазами. Команды для обоих исходов она печатает тут же.

Затем включить задачу:

```bash
schtasks /Change /TN zavod-takeover /ENABLE
```

Пока перехват идёт, задача перед каждым проходом сверяется с сервером: принимает «стоп» утверждающего и снятые записи, а вернувшемуся серверу сразу ставит отметку перехвата. Что она приняла, видно в `mirror\takeover.log` строками «сверка с сервером».

Когда сервер ожил:

```bash
npm run mirror -- --handback
```

```bash
schtasks /Change /TN zavod-takeover /DISABLE
```

Возврат сначала останавливает выпуск на компьютере, потом передаёт серверу всё сделанное и только потом включает сервер. Не передалась хотя бы одна запись: выпуск не включён нигде, команду повторяют.

Задача `zavod-takeover`, забытая включённой после возврата, ничего не выпустит: без перехвата выпуск на компьютере оператора не идёт.

## Сервер подняли из архива

Архив старше копии на этом компьютере, и сервер из архива не знает, что вышло после него. Такой сервер выпуск не ведёт (в его каталоге данных лежит файл `RESTORED`), а задача `zavod-mirror` копию на компьютере его снимком не затирает и пишет в рабочую группу. Сверить сервер с копией:

```bash
npm run mirror -- --reconcile
```

Если расписание в это время вёл компьютер, сверку делает возврат (`npm run mirror -- --handback`). Что именно сверка меняет на сервере и чего не меняет: `docs/06-РАСПИСАНИЕ-И-ДУБЛЬ.md`, раздел 8.

## Снять задачи

```bash
powershell -ExecutionPolicy Bypass -File ops\windows\install-tasks.ps1 -Remove
```
