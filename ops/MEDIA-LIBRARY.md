# Медиатека: единый процесс для всех новых материалов

## Коротко для команды

Положите новые файлы в C:\ecopolis-zavod\reference\media-inbox\<имя материала>\originals. Готовые обложки, монтаж и кадры для площадок — в publications рядом. Это входящая папка, не постоянный архив; единственный рабочий реестр находится на российском сервере. Не складывайте исходники в Temp/Downloads и не удаляйте свою копию до подтверждения импорта и независимого резервирования.

Оператор импортирует папку одним действием. Импорт закрытый: оригинал не становится доступным по ссылке и не публикуется. Каждый файл получает постоянный номер, связь с материалом, размер, формат, хеш и дату. Одинаковые байты не занимают место повторно; другая фотография того же объекта не становится новой версией первой. Замена файла с тем же логическим именем создаёт новую версию, прежняя остаётся.

Для работы выбирается отдельная версия для площадки. Фото Telegram-альбома, слайды Instagram, ролик, обложка и файл ручного пакета используют записи той же медиатеки. Смена выбранной версии снимает прежнюю актуальность согласования через изменение contentHash. Оригинал не разрешается использовать как публичное вложение.

При queue submit после успешных проверок фото отправляются нативно в тему согласования: альбомом либо одним изображением. Кнопочная карточка связана с тем же содержимым и первым фото. Отсутствие фото, неполная доставка или сетевой обрыв не заменяются строками URL; процесс останавливается для проверки. Недопустимый текст не получает ни альбома, ни кнопок.

На последнем этапе одобренной записи система получает файл из медиатеки. Новым S3-файлам ссылка выдаётся заново на момент попытки и действует семь суток, в реестре/очереди она не хранится. Поэтому ожидание слота несколько недель само по себе не делает ссылку просроченной. При недоступности хранилища материал не объявляется вышедшим. Для уже отдельно разрешённых постоянных URL сохранена совместимость.

## Оператор: импорт и версии

```powershell
npm run media -- --import="C:\ecopolis-zavod\reference\media-inbox\case-name\originals" --material=case:case-name --server=zavod@104.171.136.64
```

При импорте файла/папки сначала передаются байты и параметры в приватную media-inbox VPS, затем они попадают в постоянную media-library. Входящий пакет после успешного приёма убирается, локальные оригиналы оператора не удаляются. Ошибка сохраняет исходник и не считается успешным импортом. Ключи и файлы окружения не импортируются.

Для готовой версии одного оригинала:

```powershell
npm run media -- --import="C:\ecopolis-zavod\reference\media-inbox\case-name\publications\cover.jpg" --material=case:case-name --role=cover --parent=med_ID_ORIGINAL --variant=cover-v1 --server=zavod@104.171.136.64
```

Роли: original, publication, cover. Для publication/cover обязателен parent оригинала того же material. variant определяет назначение (telegram, instagram, монтаж и т.п.); по умолчанию это имя/относительный путь файла. При повторе того же файла в том же назначении возвращается прежний mediaId.

На VPS, под zavod, из /opt/ecopolis-zavod/current:

```bash
node src/media/upload.mjs --status
node src/media/upload.mjs --list --material=case:case-name
node src/media/upload.mjs --audit
node src/media/upload.mjs --sync=med_ID
node src/media/upload.mjs --restore=med_ID
```

sync работает только после отдельного подключения приватного S3: PUT, затем GET и проверка SHA256. Только после этого запись получает verified. restore скачивает в отдельный промежуточный файл, проверяет размер/SHA256 и не заменяет существующий файл. Содержимое и подписанные ссылки в вывод не попадают.

В карточке используется общий идентификатор:

```json
{"type":"image","mediaId":"med_32_hex_characters"}
```

Для видео type=video; обложка может ссылаться через coverMediaId. Порядок media[] определяет порядок фотографий/слайдов. Проверка не принимает оригинал, чужой material, неизвестную запись и несовпадающий тип. Существующие HTTPS-записи совместимы. Команда --file теперь по умолчанию ведёт в закрытый импорт и требует material/сервер; прежний прямой S3-загрузчик остаётся только под явным --legacy-public для отдельно согласованных старых операций.

## Где лежат данные и как восстановить

На VPS /opt/ecopolis-data/media-library/index.json — реестр; blobs/<SHA256> — закрытые файлы без публичного веб-маршрута. Приватный будущий S3 хранит originals/ и publications/ раздельно; он не совпадает с BACKUP_S3_BUCKET. Ключи MEDIA_S3_* только на сервере, штатный tokens import. На компьютере достаточно SSH-доступа, ключ S3 туда не переносится.

Локальная квота пока 512 МБ. При заполнении новый импорт останавливается; исходники автоматически не удаляются. Это рабочая ограниченная серверная медиатека, а не обещание вместить 100 ГБ на диске 29 ГБ. Подключение большого S3 и освобождение кеша не включают автоматического удаления оригиналов: необходимы подтверждённая независимая копия и отдельная согласованная политика.

ops/backup.sh включает всю media-library в ежедневную зашифрованную копию данных. Для отдельной проверки восстановления медиатеки без заявок и ключей:

```bash
bash ops/media-library-backup.sh
```

Команда создаёт зашифрованный снимок вне DATA, расшифровывает только его в отдельный временный каталог, сверяет все файлы и убирает проверочную копию. Живая медиатека не заменяется. Снимок хранится на VPS; внешняя копия проверяется отдельно. Полное восстановление реестра после потери сервера начинается с зашифрованного архива и пароля клиента; без реестра одной ссылки на S3 недостаточно. Если потерян только локальный файл при целой метадате, после проверенного S3 доступна команда restore.

Исходники и версии сохраняются до отдельного решения клиента, автоматического lifecycle/удаления нет. Штатные архивы данных VPS — 14 дней по прежней политике; отдельный проверочный media-library-снимок не удаляется автоматически. Перед ростом объёма нужно согласовать ёмкость, независимую копию и сроки снимков. Текущий внешний backup возвращает SignatureDoesNotMatch: локальная копия не защищает от полной потери VPS.

## Восстановление доставки фото на согласование

Если ответ Telegram потерян, submit не повторяет фото/карточку. Сначала оператор проверяет тему группы. Только после собственной проверки:

```bash
npm run queue -- preview-reset ИМЯ --channel=telegram --confirm-card-absent
```

Эта команда сохраняет уже подтверждённый альбом и разрешает заново отправить только отсутствующую карточку следующим submit. Если точно отсутствуют и фото, и карточка — отдельный --confirm-all-absent. Команды сами не отправляют сообщения. Нельзя использовать подтверждение без проверки группы: так можно создать дубликат. Исходный журнал состояний не стирается.
