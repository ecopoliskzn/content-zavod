# Telegram: фотоальбомы и передача файлов S1

05.11.2026. Реализация завершена и установлена основной S0 по прямому поручению оператора. Текстами, контентной карточкой и согласованием кейса владеет S1; S0 их не меняла, в очередь кейс не добавляла и не публиковала.

## Что работает в коде

- 2–10 фотографий media[] отправляются одним sendMediaGroup через multipart /upload/sendMediaGroup. Порядок массива сохраняется. Первое фото получает неизменённый entry.text и parse_mode=HTML, остальные — без подписи.
- Подпись ограничена 1024 знаками после разметки; длинный текст не обрезается. Исходная подпись кейса по передаче S1 — 571 знак. Неподдерживаемые кнопки, смешанный фото/видео-альбом, больше 10 фото и слишком большая подпись дают отказ до отправки. Реализован именно фотоальбом.
- У каждого файла уникальное attach-поле. Одинаковое имя файлов допустимо; дубли attach-полей и несопоставленные ссылки отклоняются до сети. До начала отправки загружаются все фотографии, до 10 МБ каждая и до 50 МБ суммарно.
- Одно фото сохраняет прежний sendPhoto, одиночное видео — прежний sendVideo. Для них прежняя сверка Telegram после обрыва не менялась.
- Результат альбома содержит id первого сообщения для обратной совместимости, все messageIds и mediaGroupId. Все ID сохраняются в result очереди и externalIds журнала; публикация альбома учитывается одной записью.
- Успех требует полного ответа: нужное количество уникальных ID, один media_group_id, ожидаемый канал и фото в каждом элементе. Неполный/противоречивый ответ не становится published. Наблюдавшиеся ID сохраняются отдельно для ручной проверки.
- Сетевой запрос отправки не повторяется внутри клиента. При неопределённом результате tgSending остаётся; следующая попытка блокируется для проверки человеком. Найденная на витрине подпись не доказывает полноту альбома. Полный сохранённый ответ восстанавливается без повторной отправки; проверяется отпечаток содержимого.

## Реальные фото кейса

Манифест: C:\ecopolis-zavod\content\reports\telegram\2026-11-05\salavat-media.json.
В нём точный порядок photo 4,3,2,1, HTTPS URL, размер и SHA256. S1 берёт только поля type и url для записи:

```js
const media = manifest.media.map(({type, url}) => ({type, url}));
// media[0] — фото 4; media[1] — фото 3; media[2] — фото 2; media[3] — фото 1.
```

S1 меняет только технические URL в своей карточке, сохраняя утверждённый текст, facts, ask и порядок. Для Telegram — все четыре фото; для отдельного поста Threads можно взять URL первого элемента (фото 4), учитывая фактические возможности адаптера. Для VK без пользовательского ключа остаётся штатный пакет ручной выкладки после «Одобрить». Код проверки очереди не ослаблялся: media[].url по-прежнему должен быть HTTPS; локальные пути в карточку не подставлять.

Публичные адреса: https://ecopolisgo.ru/media/<SHA256>.jpg. Все четыре фотографии проверены на VPS: HTTP 200, image/jpeg, совпадение SHA256. С компьютера оператора также проверена внешняя доступность. Изображения не изменены. Доступность URL сама по себе не подтверждает успешное получение фотографии серверами Meta; полноценная публикация Threads требует штатного одобрения и отдельной проверки результата.

Файлы лежат в отдельном /opt/ecopolis-data/public-media. Разрешены только GET/HEAD точных имён из 64 hex-символов с jpg/png/webp; списков каталога и произвольных файлов нет. Backup bucket, data/leads и файлы окружения не открывались. Явное разрешение оператора на постоянную публичную выдачу именно четырёх фото через ecopolisgo.ru получено 05.11.2026 после отказа автоматической проверки; обхода отказа не было.

## Единственный технический блокер Telegram

Read-only getMe подтвердил @EcopolisKZNbot. getChatMember для @ecopolis_kzn вернул HTTP 400: member list is inaccessible. Право публикации не подтверждено; TG_CHANNEL не включён.

Владелец должен открыть именно публичный канал @ecopolis_kzn, добавить/проверить @EcopolisKZNbot в администраторах с правом «Публикация сообщений». Администраторство в рабочей группе этого права в канале не заменяет. Затем S0 повторяет read-only probe и только после подтверждения принимает TG_CHANNEL=@ecopolis_kzn штатным импортом, сохраняя HOLD.

После устранения этого технического блокера S1 проверяет запись, ставит её в очередь и отправляет на согласование. Павел нажимает «Одобрить». Выпуск остаётся на паузе до отдельного решения оператора. Без этих действий живой успешный sendMediaGroup в канал не проверен и кейс не считается опубликованным.
