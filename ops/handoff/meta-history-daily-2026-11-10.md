# Ежедневная история Instagram и Threads — подготовка для S0 и S5

Поручение оператора 10.11.2026: наладить ежедневный серверный сбор @ecopolis_kzn. Это Node-задача cron без вызовов ChatGPT, нового доступа и сообщений в группу.

## Код и данные

src/metrics/meta-history.mjs использует существующий collectBaseline с отключённым запросом текстов. Только собственные профили, ID/ссылки/даты материалов, числовые метрики, времена, периоды, полнота и безопасные коды ошибок. Окно материалов60 дней; insights свежих до14 дней — ежедневно, старше — по понедельникам МСК. Неполученное значение=null с причиной; намеренно не запрошенное=status not_due. Метаданные старых материалов могут обновляться вместе с описью без отдельных запросов insights. История Stories/отдельная лента собственных ответов Threads не покрыты. Счётчик ответов не считается числом клиентов.

Каждый день — /opt/ecopolis-data/meta/history/YYYY-MM-DD.json (дата МСК,0600). В файле snapshot, воспроизводимый aggregate и comparison. Файл атомарно создаётся без замены; повтор дня не делает API-запросов. Повреждённый файл дня не заменяется. Ошибка одной площадки сохраняется и даёт exit2; она не превращается в нулевые показатели. Повторный автоматический запуск того же частичного дня не скрывает ошибку новым снимком. Замок приложения и внешний flock не допускают двух сборщиков.

Сравнение только общих ID и совместимых определений метрик, с точными временами. Отрицательные изменения сохраняются и помечаются поправкой счётчика. Новые/не обнаруженные ID идут отдельно; отсутствие в окне не доказывает удаления поста. Предыдущая база выбирается из последнего пригодного дневного файла и исторических baseline; ошибки чтения старых файлов отмечаются warnings. Октябрьские исходники не изменяются. Для сравнения за неделю S5 может вызвать чистую compareSnapshots для двух выбранных снимков, сохраняя условия сопоставимости.

## Точная установка основной S0

1. Проверить точечный коммит и совместимость, выполнить одну общую штатную установку поверх текущей версии. Никакой второй сервис/runner/публикация не нужен.
2. Проверить UTC сервера. Добавить только одну задачу к реально действующему crontab пользователя zavod; не устанавливать весь ops/crontab.txt, поскольку он содержит другие пока не включённые задачи.
3. Строка: `20 4 * * * /usr/bin/flock -n /tmp/zavod-meta-history.lock /usr/bin/node /opt/ecopolis-zavod/current/src/metrics/meta-history.mjs >> /var/log/zavod/meta-history.log 2>&1`. Это07:20 МСК ежедневно. При уже существующем сборщике согласовать единый запуск, не добавлять дубль.
4. Проверить лог на запись пользователем zavod. Запустить установленную команду один раз для текущего дня; проверить безопасную структуру файла и полноту обеих площадок. Второй запуск должен вернуть ALREADY_COLLECTED без новых запросов, bytes файла не меняются. Не печатать .env или сырые ответы API.
5. Подтвердить реальный VERSION/health, точную единственную cron-строку и ручную пробу. Будущий запуск cron не считать проверенным до наступления07:20; текущий ручной проход проверяет работоспособность команды.

## Для S5

Датированные дневные файлы: /opt/ecopolis-data/meta/history/. Числовой источник10ноября и сравнение с19октября сохранены отдельно в content/reports/meta/2026-11-10/. Использовать канонические октябрьские .source/.aggregate, не предварительные data/summary. Восьминедельное окно стартового отчёта, текущие60дней и количество разных ID нельзя смешивать как изменение эффективности. Требовать отдельно факт установки, первый снимок и факт будущего автоматического прохода. На момент этого handoff код подготовлен локально; установка/расписание ещё не подтверждены.
