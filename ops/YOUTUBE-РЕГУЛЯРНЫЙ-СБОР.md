## Подготовленное поведение

`npm run metrics -- --channel=youtube` сохраняет обычные метрики журнала и отдельно весь доступный владельцу архив через собственный OAuth. Включены все страницы uploads и видео, а также privacy/status. Чужой канал OAuth не принимается. API key не требуется.

История находится только в каталоге данных: `youtube/history/YYYY-MM-DD.json`. Снимок за день не перезаписывается; параллельные проходы разделены замком. Повторный проход после успеха не опрашивает весь архив заново. Если страница Data API не дочитана, снимок не сохраняется и ложного исчезновения роликов не возникает. Отказ Analytics не стирает полную опись Data API, но состояние отмечается явно и команда возвращает код 2. Досмотр без данных не становится нулём.

`youtube/latest.json` содержит последний снимок и сравнения день/неделя/первая база; передаётся в `mirror/youtubeHistory.json`. Имена авторов комментариев и тексты описаний в этот поток не входят. Статусы public/unlisted/private/unknown разделены. `unavailable` означает, что видео есть в загрузках, но Data API не вернул его сведения. `noLongerAccessible` — видео отсутствует в новом полном перечне; это НЕ доказательство удаления.

В сравнении `commonDelta` — изменение накопленных счётчиков только тех же видео с измерениями на обе даты. `commonMeasured` показывает размер этого набора. Добавления, утрата доступности и смены статуса идут отдельно. Дельта счётчика не заменяет отчёт Analytics о просмотрах за период, отрицательные корректировки не скрываются. Даты реальной базы и длительность сравнения всегда указаны: пробелы в ежедневном сборе не выдаются за ровно семь дней. Недельная история не появляется раньше накопления базы. Локальный архив аудита оператора `C:/ecopolis-zavod/content/reports/youtube/2026-10-17/baseline-1792220635361.json` остаётся материалом профильных сессий и не входит в поставку Git. В серверную историю он автоматически не импортирован и прошлые даты не выдумываются. Рабочие ежедневные снимки создаёт код `src/metrics/youtube-history.mjs` на фактическую дату сбора.

`src/comments/collect.mjs --only=youtube` читает собственным OAuth все страницы опубликованных веток и все страницы ответов. Читает ответы даже под собственной корневой репликой компании; собственные реплики отфильтровываются до сохранения. Автор, его аккаунт и аватар не записываются. Сбор не включает heldForReview/likelySpam и не утверждает охват недоступных API комментариев. Пагинация защищена от повторяющегося pageToken. Ошибка страницы не выдаётся за полный успешный проход.

Комментарии старше 21 дня сохраняются как `archived`, без новой карточки вопроса. Свежий ответ под старой веткой остаётся новым по собственной дате. У существующей записи обновляются изменённый текст и число ответов без потери статуса согласования/ответа. Порядок приватности снимка остаётся прежним: `privacy.shareComments` и обезличивание `publicComments`. Сырые тексты не читать на компьютере и в сессии.

Живой сбор комментариев (даже --dry) на компьютере оператора запрещён до чтения файла и сетевого вызова. CLI выводит только числа/состояние, не фрагменты текста. На VPS пишется `comments-health.json` со временем попытки, последнего полного успеха, источниками и охватом; в mirror передаётся `commentsHealth.json` без текстов людей.

Для metrics/comments/weekly исправлен запуск через current-симлинк: ранее import URL и argv указывали разными путями на один файл, поэтому cron-команда могла молча завершиться, не выполнив работу.

Недельный отчёт включает архив канала по последнему снимку ДО конца отчётной недели. `npm run report -- --save` сохраняет файлы без сообщения в группу. `--send` — отдельное действие, не включено предлагаемым расписанием.

1. После проверяемого коммита согласовать выкладку с оператором. Выкладывать штатным `ops/deploy.sh`; HOLD, ALERTS_MUTED=1 и юридический затвор не менять.
2. Ещё раз проверить текущий crontab. Добавить только три отсутствующих задания из `ops/youtube-observation-cron.txt`, сохранив backup/runner и иные новые задания. Нельзя целиком устанавливать общий ops/crontab.txt: он включает дополнительные отправки и чужие процессы.
3. Под zavod запустить метрики YouTube вручную; проверить код выхода, количество и статусы, дату Analytics, наличие полного снимка. Вывод — только агрегаты. Запустить комментарии без --send и проверить числом health/coverage, не печатая тексты. Проверить недельный --save. До накопления дат не обещать недельные изменения.
4. После фактического времени cron проверить свежесть снимка и lastSuccessAt, коды/журналы только агрегатами. Один ручной успех не доказывает ежедневный cron. До этих проверок регулярный сбор считать подготовленным, но не работающим.
