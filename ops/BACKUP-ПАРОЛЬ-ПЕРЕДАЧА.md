# Отдельная копия пароля резервных копий

Подготовлено 15.10.2026. Пароль пока только на VPS, передача клиенту не завершена.

Выбран защищённый файл. Подготовлены `ops/windows/export-backup-password.ps1`, `ops/backup-envelope.mjs` и автономная страница `ops/windows/backup-password-open.html`. Экспорт запускает оператор: дважды вводит новый пароль передачи (не менее 16 символов), скрипт переносит исходный пароль через scp во временный каталог с закрытым ACL, шифрует AES-256-GCM с PBKDF2-SHA256 (600000 итераций), проверяет расшифровку и удаляет временный каталог. Пароль передачи идёт в процесс по stdin, не через аргументы. Готовый JSON находится в `.local-secrets/handoff/`, исключённом из Git. Реальный экспорт ещё не запущен: пароль передачи задаёт человек.

Клиенту передаются JSON и автономный HTML; пароль передачи сообщается отдельным защищённым способом. Клиент открывает HTML локально в Edge/Chrome, выбирает JSON и вводит пароль передачи. Интернет для расшифровки не нужен. После проверки клиент скрывает значение кнопкой очистки и хранит файл отдельно от пароля передачи. Исполнитель не запрашивает полученное значение в чате.

Источник — `/opt/ecopolis-data/.backup-pass`. Его нельзя печатать в терминал, чат, журнал или помещать в Git. Перевыпускать пароль для передачи не требуется: старые архивы зашифрованы существующим паролем.

## Что передаётся

Только пароль расшифровки, без архива с данными, S3-ключей и окружения приложения. Карточка хранения: «Экополис — пароль резервных копий VPS», дата создания копии и назначение. Адрес сервера и инструкция восстановления могут храниться рядом как несекретные сведения. Запись должна принадлежать клиенту и быть доступна ответственному при утрате VPS и компьютера исполнителя.

## Вариант с менеджером паролей

Владелец выбирает своё хранилище и открывает новую защищённую запись. Значение переносится технически без отображения в сессии; конкретный способ зависит от поддерживаемого импорта. Пароль менеджера, recovery-коды и мастер-пароль остаются у владельца. Доступ исполнителю ко всему хранилищу не выдаётся.

## Вариант с защищённым файлом

Нужен независимый способ расшифровки у клиента: его публичный ключ либо пароль, вводимый владельцем непосредственно в инструмент шифрования и сохраняемый отдельно. Windows DPAPI компьютера исполнителя не подходит как единственная защита для передачи другому человеку или на другой компьютер. Не следует класть пароль расшифровки в тот же архив или передавать его тем же сообщением.

## Проверка завершения

Клиент подтверждает, что открыл запись или расшифровал файл на своём устройстве. Совпадение проверяется отпечатком без отображения значения. Затем удаляются временные файлы передачи. Серверный оригинал остаётся: он нужен для следующих резервных копий. До этой проверки нельзя писать, что пароль хранится у клиента.
