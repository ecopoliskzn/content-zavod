# Instagram и Threads: месяц через приложение исполнителя, потом своё

У клиента пока нет учётной записи разработчика Meta. Первый месяц Instagram и Threads работают через приложение исполнителя (`kormishin-bot`). Этот документ описывает, как подключить, что проверить в первый день и как переехать.

## 1. Что нужно от клиента до подключения

- [ ] Аккаунт Instagram переведён в профессиональный: «Настройки → Тип аккаунта → Переключиться на профессиональный аккаунт» («компания»). Личный аккаунт к API не подключается никак.
- [ ] Известно точное имя аккаунта Instagram и аккаунта Threads. С сайта клиента они не подтверждены.
- [ ] Владелец аккаунтов на связи с телефоном в руках: вход занимает десять минут, но делает его только он.
- [ ] Подписан договор-поручение (`legal/01`) и регламент доступов (`legal/03`).

## 2. Подключение Instagram

Делается на созвоне с владельцем аккаунта.

1. Исполнитель в кабинете своего приложения: «Роли приложения → Роли → Добавить людей → Тестировщик Instagram», вводит имя аккаунта клиента.
2. Владелец аккаунта в Instagram: «Настройки → Сайты и приложения → Приглашения тестировщика → Принять».
3. Исполнитель формирует ссылку для входа (образец скрипта: `reference/bot-alyona/scripts/ig-token.mjs`, флаг `--url`). Права запрашиваются сразу все: `instagram_business_basic`, `instagram_business_content_publish`, `instagram_business_manage_comments`, `instagram_business_manage_messages`, `instagram_business_manage_insights`. Задним числом право не добавить: нужен новый вход.
4. Владелец открывает ссылку **на своём телефоне**, входит своим аккаунтом, нажимает «Разрешить». Его перебрасывает на страницу исполнителя с кодом.
5. Исполнитель обменивает код на маркер на 60 дней. Маркер, номер аккаунта и дата истечения кладутся в файл окружения **сервера клиента**: `IG_TOKEN`, `IG_USER_ID`, `IG_TOKEN_EXPIRES`. Значение маркера в переписку и в вывод не попадает.
6. Подписка аккаунта на события: `node -e "import('./src/channels/instagram.mjs').then(m => m.subscribe()).then(r => console.log(r.kind, r.error || ''))"`.
7. В окружении сервера исполнителя в карту пересылки добавляется пара «номер аккаунта клиента = адрес сервера клиента `/ig/webhook`». Перед этим нужна правка пересылки: см. раздел 4.

Проверка: `npm run doctor -- --live` на сервере клиента должен показать имя аккаунта и тип «BUSINESS».

## 3. Подключение Threads

Threads — отдельный продукт Meta со своим входом и своим маркером.

1. В приложении исполнителя должен быть включён сценарий «Доступ к Threads API». Аккаунт клиента добавляется тестировщиком Threads.
2. Владелец принимает приглашение: в Threads «Настройки → Аккаунт → Разрешения сайтов → Приглашения».
3. Вход по ссылке `https://threads.com/oauth/authorize` с правами `threads_basic`, `threads_content_publish`, `threads_manage_insights`, `threads_manage_replies`, `threads_read_replies` (образец: `reference/bot-alyona/scripts/threads-token.mjs`).
4. Обмен кода на короткий маркер, затем на длинный (60 дней). В окружение сервера клиента: `THREADS_TOKEN`, `THREADS_USER_ID`, `THREADS_TOKEN_EXPIRES`.

**Риск.** В прошлом запуске Threads через общее приложение не заработал, и аккаунт перевели на собственное приложение владельца. Если повторится: Threads ждёт своего приложения клиента (раздел 6), а его слоты на это время отдаются Telegram и ВКонтакте.

## 4. Правка пересылки на стороне исполнителя

Сейчас сервер исполнителя пересылает событие чужого аккаунта **целиком и с подписью своего приложения**. Для своих проектов это годится, для внешнего клиента нет:

- чтобы проверить такую подпись, серверу клиента нужен секрет приложения исполнителя. Отдавать его нельзя: с ним можно подделать события любого аккаунта приложения;
- в одном запросе Meta может прислать события нескольких аккаунтов. Тогда на сервер клиента уйдут чужие события.

Правка описана в `docs/patches/kormishin-site-ig-forward.md`: клиенту уходят только его записи, подписанные отдельным секретом пары (`IG_FORWARD_SECRET`). Сервер клиента такой заголовок уже понимает.

**До правки** сообщения в директ через пересылку не подключаются. Кодовые слова в комментариях работают опросом (`IG_POLL=1`), публикации работают без всякой пересылки.

## 5. Проверки первого дня

Каждая проверка делается живым действием, а не чтением настроек.

| Что проверяем | Как | Что считается успехом |
|---|---|---|
| Маркер Instagram | `npm run doctor -- --live` | имя аккаунта, тип, остаток суточного предела публикаций |
| Хранилище видно Meta | загрузить тестовую картинку, создать контейнер | статус контейнера `FINISHED` |
| Публикация рилса | одна тестовая запись через очередь, от согласования до ссылки | рилс в ленте, ссылка в журнале |
| Кодовое слово в директе | написать слово с чужого аккаунта | ответ со ссылкой в бота в течение минуты |
| Кодовое слово в комментарии | оставить слово под рилсом с чужого аккаунта | личное сообщение и «Отправили…» под комментарием; при опросе до пяти минут |
| Маркер Threads | `npm run doctor -- --live` | имя аккаунта |
| Ветка Threads | тестовая запись из двух реплик | обе реплики в профиле, ссылка в журнале |
| Продление маркеров | `npm run tokens -- --refresh --force` на следующий день | новая дата истечения, подписка оформлена заново |

Тестовые публикации после проверки удаляет владелец аккаунта в приложении.

## 6. Переезд на своё приложение клиента

Начинается в первую неделю, идёт параллельно с работой завода.

**Неделя 1**

1. Бизнес-портфолио Meta на компанию: business.facebook.com, владелец — сотрудник клиента с рабочей почтой.
2. Учётная запись разработчика: developers.facebook.com, тем же человеком.
3. Приложение типа «Компания», привязанное к портфолио. Сценарии: «Управление сообщениями и контентом в Instagram» (вход через Instagram) и «Доступ к Threads API».
4. В приложении: адрес политики конфиденциальности клиента, значок, категория.

**Недели 1–3**

5. Подтверждение компании в портфолио: документы юрлица (выписка ЕГРЮЛ, документ с адресом и телефоном). Meta проверяет от нескольких дней до нескольких недель.
6. Перевод приложения в режим «Опубликовано». События приходят только в этом режиме.
7. Вебхук приложения: адрес `https://<адрес завода>/ig/webhook`, слово подтверждения из `IG_WEBHOOK_VERIFY_TOKEN`, поля `comments` и `messages`.

**Неделя 4: переключение (один созвон, около часа)**

8. Владелец аккаунтов входит заново, уже через приложение клиента. Новые маркеры кладутся в окружение сервера.
9. В окружение сервера: `IG_APP_SECRET` и `IG_WEBHOOK_VERIFY_TOKEN` своего приложения. `IG_FORWARD_SECRET` убирается.
10. Подписка аккаунта на события новым маркером.
11. Проверки из раздела 5 заново, все восемь.
12. Исполнитель удаляет аккаунты клиента из своего приложения и пару из карты пересылки.
13. Акт (`legal/04`).

**Расширенный доступ.** Свой аккаунт, у которого есть роль в своём приложении, работает на стандартном доступе. Расширенный доступ (проверка приложения Meta с видеозаписью сценария) нужен, только если события о комментариях не приходят и на своём приложении. Тогда опрос остаётся включённым, а заявка на проверку подаётся отдельно.

## 7. Если что-то пошло не так

| Признак | Причина | Что делать |
|---|---|---|
| Вход возвращает ошибку «Invalid platform app» | сценарий Instagram не добавлен в приложение либо адрес возврата не в списке | проверить настройки сценария |
| Маркер выдан, вызовы отвечают «does not have permission» | право не было запрошено при входе | новый вход со всеми правами |
| Публикация отвечает «Media download has failed» | Meta не забирает файл по адресу | другое хранилище; повтор через минуту |
| Кодовое слово в директе молчит | нет подписки на события либо пересылка не настроена | `subscribe()`; проверить карту пересылки |
| Всё работало и перестало | маркер продлён, подписка слетела | продление в заводе оформляет её само; проверить журнал `tokens.log` |
| «Application request limit reached» | слишком частые вызовы | опрос реже; цифры раз в сутки |
