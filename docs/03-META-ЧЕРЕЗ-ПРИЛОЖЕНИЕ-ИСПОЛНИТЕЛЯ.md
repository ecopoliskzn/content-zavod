# Instagram и Threads: месяц через приложение исполнителя, потом своё

У клиента пока нет учётной записи разработчика Meta. Первый месяц Instagram и Threads работают через приложение исполнителя (`kormishin-bot`). Этот документ описывает, как подключить, что проверить в первый день и как переехать.

**Кто что делает.** Завод ведёт клиент: оператор завода — его сотрудник. Вход в первый месяц оформляет исполнитель на своём компьютере, потому что секрет его приложения клиенту не передаётся. Выданный маркер он кладёт на сервер клиента и у себя не оставляет. События аккаунта (комментарии, сообщения) на сервер исполнителя не идут: подписка на них в первый месяц не оформляется (решение владельца 10.10.2026, раздел 4).

## 1. Что нужно от клиента до подключения

- [ ] Аккаунт Instagram переведён в профессиональный: «Настройки → Тип аккаунта → Переключиться на профессиональный аккаунт» («компания»). Личный аккаунт к API не подключается никак.
- [ ] Известно точное имя аккаунта Instagram и аккаунта Threads. С сайта клиента они не подтверждены.
- [ ] Владелец аккаунтов на связи с телефоном в руках: вход занимает десять минут, но делает его только он.
- [ ] Утверждён регламент доступов (`legal/03`). Подключение идёт в первую неделю, пока у исполнителя есть ключ SSH к серверу и приём заявок закрыт.

## 2. Подключение Instagram

Делается на созвоне с владельцем аккаунта.

1. Исполнитель в кабинете своего приложения: «Роли приложения → Роли → Добавить людей → Тестировщик Instagram», вводит имя аккаунта клиента.
2. Владелец аккаунта в Instagram: «Настройки → Сайты и приложения → Приглашения тестировщика → Принять».
3. На компьютере исполнителя в `.env.local` его копии набора лежат номер и секрет его приложения и адрес страницы возврата: `META_IG_APP_ID`, `META_IG_APP_SECRET`, `META_IG_REDIRECT_URI`. Ни на сервер клиента, ни на компьютер оператора клиента эти три строки не попадают никогда.
4. Исполнитель формирует ссылку для входа:

   ```bash
   npm run meta -- --platform=instagram --url
   ```

   Права запрашиваются сразу все: основной доступ, публикация, комментарии, сообщения, цифры. Задним числом право не добавить: нужен новый вход.
5. Владелец открывает ссылку **на своём телефоне**, входит своим аккаунтом, нажимает «Разрешить». Его перебрасывает на страницу возврата с кодом. Код живёт час.
6. Исполнитель обменивает код на маркер на 60 дней:

   ```bash
   npm run meta -- --platform=instagram --code=<код>
   ```

   Команда пишет в `.env.local` маркер, номер и имя аккаунта и дату истечения (`IG_TOKEN`, `IG_USER_ID`, `IG_USERNAME`, `IG_TOKEN_EXPIRES`) и печатает только имя, номер и срок.
7. Маркер переносится на сервер клиента файлом, минуя чат и буфер обмена:

   ```bash
   npm run tokens -- --export=IG_TOKEN,IG_USER_ID,IG_USERNAME,IG_TOKEN_EXPIRES --out=meta.env
   ```

   ```bash
   scp meta.env zavod@<адрес сервера>:/tmp/meta.env
   ```

   На сервере:

   ```bash
   cd /opt/ecopolis-zavod/current && node src/tokens/check.mjs --import=/tmp/meta.env
   ```

   Приём вписывает строки в файл окружения и удаляет принесённый файл. Подписку на события он пропускает и пишет об этом: своего приложения у клиента ещё нет (`IG_APP_SECRET` пуст). Файл `meta.env` и четыре строки `IG_*` на компьютере исполнителя после этого удаляются: маркер клиента живёт только на сервере клиента и продлевается там сам, секрет приложения для продления не нужен.
8. В окружении сервера клиента включается опрос комментариев: `IG_POLL=1`.

Проверка: `npm run doctor -- --live` на сервере клиента должен показать имя аккаунта и тип «BUSINESS».

## 3. Подключение Threads

Threads — отдельный продукт Meta со своим входом и своим маркером.

1. В приложении исполнителя должен быть включён сценарий «Доступ к Threads API». Аккаунт клиента добавляется тестировщиком Threads.
2. Владелец принимает приглашение: в Threads «Настройки → Аккаунт → Разрешения сайтов → Приглашения».
3. Вход по ссылке, те же два шага, что у Instagram. Права берутся все: публикация, цифры, чтение ответов.

   ```bash
   npm run meta -- --platform=threads --url
   ```

   ```bash
   npm run meta -- --platform=threads --code=<код>
   ```

4. **Если вход по ссылке не проходит**, маркер выдаёт генератор в консоли Meta: приложение → «Threads API» → маркеры пользователя. Так мы делали в прошлом запуске. Генератору нужны пять условий разом: права в приложении, роль тестировщика, принятое приглашение, открытый профиль и живой сеанс на threads.com. Маркер из консоли вставляется в скрытую строку ввода:

   ```bash
   npm run meta -- --platform=threads --paste
   ```

5. Команды первого месяца выполняет исполнитель на своём компьютере, как и у Instagram. Перенос на сервер клиента тем же порядком: `--export=THREADS_TOKEN,THREADS_USER_ID,THREADS_USERNAME,THREADS_TOKEN_EXPIRES`, затем `--import` на сервере.

**Риск.** В прошлом запуске Threads через общее приложение не заработал, и аккаунт перевели на собственное приложение владельца. Если повторится: Threads ждёт своего приложения клиента (раздел 6), а его слоты на это время отдаются Telegram и ВКонтакте.

## 4. События в первый месяц: пересылки нет

**Решение владельца 10.10.2026: пересылка событий через сервер исполнителя не включается.** Завод ведёт клиент, и исполнитель не должен видеть комментарии и сообщения его подписчиков. Поэтому аккаунт клиента в первый месяц на события не подписывается вовсе: программа пропускает подписку, пока в окружении нет секрета своего приложения.

Что из этого следует:

- публикации работают как обычно: им события не нужны;
- кодовое слово в комментарии работает опросом раз в пять минут (`IG_POLL=1`);
- кодовое слово, написанное сразу в директ, в первый месяц **не работает**. В подписях стоит «напишите в комментарии»;
- после переезда на своё приложение (раздел 6) подписка оформляется, и директ начинает отвечать.

Почему нельзя было просто переслать. Сервер исполнителя умеет пересылать событие чужого аккаунта, но **целиком и с подписью своего приложения**:

- чтобы проверить такую подпись, серверу клиента нужен секрет приложения исполнителя. Отдавать его нельзя: с ним можно подделать события любого аккаунта приложения;
- в одном запросе Meta может прислать события нескольких аккаунтов. Тогда на сервер клиента уйдут чужие события.

Правка, которая это чинит, описана в `docs/patches/kormishin-site-ig-forward.md`. Она не применяется: даже исправленная пересылка проводит сообщения людей через чужой сервер, а это потребовало бы поручения на обработку данных и строки об исполнителе в согласии.

## 5. Проверки первого дня

Каждая проверка делается живым действием, а не чтением настроек.

| Что проверяем | Как | Что считается успехом |
|---|---|---|
| Маркер Instagram | `npm run doctor -- --live` | имя аккаунта, тип, остаток суточного предела публикаций |
| Хранилище видно Meta | загрузить тестовую картинку, создать контейнер | статус контейнера `FINISHED` |
| Публикация рилса | одна тестовая запись через очередь, от согласования до ссылки. Без кодового слова в подписи | рилс в ленте, ссылка в журнале |
| Маркер Threads | `npm run doctor -- --live` | имя аккаунта |
| Ветка Threads | тестовая запись из двух реплик | обе реплики в профиле, ссылка в журнале |
| Продление маркеров | `npm run tokens -- --refresh --force` на следующий день | новая дата истечения; команда сообщает, что подписка на события не оформляется: своего приложения ещё нет |

Тестовые публикации после проверки удаляет владелец аккаунта в приложении.

**Кодовые слова в первый день не проверяются.** Ответы на слова закрыты в коде, пока клиент не утвердил тексты согласий и не подтвердил уведомления в Роскомнадзор (`src/leads/legal.mjs`). Проверка слов в первый день показала бы «не работает» при исправной связи. Эти две проверки делаются в день открытия приёма, в сессии S3:

| Что проверяем | Как | Что считается успехом |
|---|---|---|
| Кодовое слово в комментарии | оставить слово под рилсом с чужого аккаунта, **после** открытия приёма | личное сообщение и «Отправили…» под комментарием; при опросе до пяти минут |
| Кодовое слово в директе | написать слово с чужого аккаунта. Только после переезда на своё приложение (раздел 6) | ответ со ссылкой в бота в течение минуты |

Комментарий, оставленный до открытия приёма, бот не догоняет: первый проход опроса после открытия только запоминает то, что уже лежит под публикациями. Поэтому слово для проверки пишется после открытия, а публикаций со словом до открытия не бывает: их не выпускает проверка готовности.

## 6. Переезд на своё приложение клиента

Начинается в первую неделю, идёт параллельно с работой завода.

**Неделя 1**

1. Бизнес-портфолио Meta на компанию: business.facebook.com, владелец — сотрудник клиента с рабочей почтой.
2. Учётная запись разработчика: developers.facebook.com, тем же человеком.
3. Приложение типа «Компания», привязанное к портфолио. Сценарии: «Управление сообщениями и контентом в Instagram» (вход через Instagram) и «Доступ к Threads API».
4. В приложении: адрес политики конфиденциальности клиента, значок, категория.

**Недели 1–3**

5. Подтверждение компании в портфолио: документы юрлица (выписка ЕГРЮЛ, документ с адресом и телефоном). Meta проверяет от нескольких дней до нескольких недель.
6. Перевод приложения в режим «Опубликовано». События приходят только в этом режиме.
7. Вебхук приложения: адрес `https://<адрес завода>/ig/webhook`, слово подтверждения из `IG_WEBHOOK_VERIFY_TOKEN`, поля `comments` и `messages`.

**Неделя 4: переключение (один созвон, около часа)**

8. В настройках своего приложения страницей возврата записан адрес завода: `https://<адрес завода>/cb/meta`. На компьютере оператора клиента в `META_IG_*` и `META_THREADS_*` теперь лежат номер и секрет приложения клиента: с этого дня вход оформляет сам оператор, исполнитель в нём не участвует. Владелец аккаунтов входит заново: те же команды `npm run meta`, тот же перенос файлом. Новые маркеры кладутся в окружение сервера.
9. В окружение сервера: `IG_APP_SECRET` (секрет своего приложения: им подписаны события) и `IG_WEBHOOK_VERIFY_TOKEN`. 
10. Подписка аккаунта на события новым маркером: приём ключей оформляет её сам, как только видит `IG_APP_SECRET`. С этого шага начинает работать кодовое слово в директе.
11. Проверки из раздела 5 заново, обе таблицы: к четвёртой неделе приём заявок открыт, и кодовые слова проверяются вместе с остальным.
12. Исполнитель удаляет аккаунты клиента из своего приложения.
13. Акт (`legal/04`).

**Расширенный доступ.** Свой аккаунт, у которого есть роль в своём приложении, работает на стандартном доступе. Расширенный доступ (проверка приложения Meta с видеозаписью сценария) нужен, только если события о комментариях не приходят и на своём приложении. Тогда опрос остаётся включённым, а заявка на проверку подаётся отдельно.

## 7. Если что-то пошло не так

| Признак | Причина | Что делать |
|---|---|---|
| Вход возвращает ошибку «Invalid platform app» | сценарий Instagram не добавлен в приложение либо адрес возврата не в списке | проверить настройки сценария |
| Маркер выдан, вызовы отвечают «does not have permission» | право не было запрошено при входе | новый вход со всеми правами |
| Публикация отвечает «Media download has failed» | Meta не забирает файл по адресу | другое хранилище; повтор через минуту |
| Кодовое слово в директе молчит | первый месяц так и задумано (раздел 4). После переезда: нет подписки на события | `npm run tokens -- --refresh --force` оформит подписку; проверить `IG_APP_SECRET` |
| Всё работало и перестало | маркер продлён, подписка слетела | продление в заводе оформляет её само; проверить журнал `tokens.log` |
| «Application request limit reached» | слишком частые вызовы | опрос реже; цифры раз в сутки |
