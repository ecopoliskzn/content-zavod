# Контракт целей S3 → S2/S0, 08.11.2026

S3 меняет только intake/runtime/targets и свои тесты. Delivery/adapters — S2; server/dispatch/config/deploy — S0. Это контракт к расширению, а не утверждение боевой готовности API. Активный служебный приём темы 309 и закрытый приём клиентских заявок не переопределяются.

`target = {channel,format,delivery_mode,account_ref,readiness,verified_at}`. Поддерживаются все восемь каналов реестра; фактические пути/аккаунты задаёт и проверяет S0. `readiness:passed|not_ready`, `delivery_mode:auto|manual`; у not_ready обязательна `reason`. Наличие схемы не ставит passed. В карточке показывается ручной путь/конкретный отказ.

Форматы → queue.kind: `text|post → post` (Telegram/ВК/бот), `thread → thread` (Threads), `article → article` (Дзен); `album → post` (Telegram), `photopost|photo-post → post` (ВК), `carousel → carousel` (Instagram); `short → short` (YouTube/Rutube), `video → video` (YouTube/ВК/Rutube), `video → post` (Telegram), `reel → reel` (Instagram), `story → story` (Instagram). Для текста mediaIds=[] допустимо. Видеоформат требует видео; фотоформат требует фото. Смешанный комплект требует явного выбора для каждого target; все файлы не подставляются во все варианты автоматически. Строгое соответствие описывает `targetSpec`, ВК short не обещается.

Новый job `protocolVersion:2`, `recipient:S1|S2`, `manifestRevision`, `revision`, `inputHash`, `input.targets` и `targets` совпадают. Если есть выбранный видеоформат — один координатор S2, иначе S1. Исполнитель с иной ролью claim не получает; requestId сохраняет идемпотентность. Уже сохранённые legacy jobs без protocolVersion не теряют действующее владение. На материал одна текущая готовая версия; старый claimed освобождается явно, queued старой ревизии superseded.

**Несколько форматов одного канала поддерживаются:** стабильный `targetKey(t)=channel+':'+format`. Variant/receipts/sync/dedupe — по exact targetKey, не одному channel. `targetEntryName(job,t)` из нового `media-intake-targets.mjs`: если у канала один вариант, совместимое `mi-<materialId>-<revision>`; если больше одного, суффикс `-<6hex SHA256(targetKey)>`. Имя проверяется на <=32. Не заменять карусель сторис и не перезаписывать квитанцию по одному Instagram. S2 использует ту же функцию для canonical entry/claim результатов, S0 — exacttarget в dispatch/sync. Готовность карусели не доказывает готовности story/API.

Результат: `variants[]` — один элемент на выбранный target; `channel`, `format`, `text` (для thread/article допускается также entry.posts/title), `mediaIds[]`, `entry`. Queue.kind должен соответствовать формату; файл/cover, факты, описание и остальные содержательные поля проверяет канонический delivery S2. Общие verified facts находятся в input.facts; per-target факты — в input.targetFacts[targetKey], только явно проверенные источники, не выдуманный список модели. В variant.entry факты должны быть разрешённым соответствующим набором. input.targetMedia[targetKey] содержит выбранные исходные mediaId; результат использует только проверенные производные публикационные версии этих исходников. Исходники никогда не publication refs.

Вход: новый свободный текст допустим только от разрешённого автора в настроенной теме материалов (команды `/…` не захватываются). Цели и форматы выбираются кодом по подтверждённому составу; неподходящие варианты не передаются редактору. Кнопки «Подготовить так»/форматов/срока не являются Одобрить.

Текущее after_approval = commissioning; choose_later удерживает submit. at/not_before принимаются только как однозначное указанное время, показываются в Москве. Изменение времени не требует новой генерации содержания; после попадания в очередь срок меняет штатный queue move, собственная запись очереди запрещена.

Сквозной тест `media-intake.test.mjs` (аннотация источника → result → review) проходит submit двух вариантов, но карточка не видит review.
