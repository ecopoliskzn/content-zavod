# Редакторский результат S2 → очередь

Редактор работает по конкретному назначенному job ID, без опроса истории моделью. `node src/bot/media-intake-cli.mjs claim --id=<job> --owner=S2` создаёт закрытую квитанцию. Токен не выводится в чат, не коммитится и не переносится в публикационный материал. Затем `context --claim=<receipt>` получает актуальный закреплённый контекст. `facts --claim=<receipt> --file=<facts.json>` обновляет проверенные факты и inputHash. Перед результатом перечитать context. `result --claim=<receipt> --result=<result.json>` передаёт результат, но не одобряет публикацию. Неясность разрешается штатным question/release, без выдумывания фактов.

Результат содержит inputHash, editorialReview `{result:"passed",policyVersion:<из context>}` и variants по одному на exact targetKey `channel:format`. Passed ставится после содержательной проверки источников, речи/текста в кадре, подписей, прав, запрета детей и рекламы по редполитике. Механическая проверка не заменяет эту работу. Обязательно просмотреть именно конечные публикационные файлы/закрытые превью каждого mediaId и обложки; весь ролик со звуком, а не один кадр. Brief и JSON этого не доказывают. Просмотр выполняется доступным закрытым локальным/служебным путём без публикации оригиналов. Если точные файлы или полный просмотр со звуком недоступны, остановить результат и задать question о конкретном недостающем доступе/проверке; passed в таком случае запрещён.

Variant: `{channel,format,text,mediaIds:[],entry}`. Entry содержит точные channel/kind/name/material, text равный variant.text, facts из закреплённого input.facts либо input.targetFacts[targetKey/channel]. Имя вычисляется targetEntryName из media-intake-targets.mjs. Для нескольких форматов одного канала сохраняется детерминированный суффикс; legacy одиночный формат сохраняет старое имя. Срок поступает исключительно из job.input.timing; choose_later удерживает отправку.

Допустимые содержательные поля entry: title, text, posts, media, facts, tags, hashtags, series; также служебные identity/date/time. Статус, approval, result, произвольные поля и URL редактора отвергаются. Media содержит только type/image|video, mediaId, для видео необязательный coverMediaId. Все медиа и обложки — проверенные по реальным байтам публикационные дочерние версии исходников этого job и material. Исходники остаются закрытыми. Основной видеофайл нельзя заменять снимком из видео. mediaIds перечисляет основные вложения в том же порядке; обложки связаны через coverMediaId.

Форматы определяет targetSpec: Telegram text/post/album/video (video → kind post), ВК text/post/photopost/photo-post/video, Threads thread, Дзен article, Instagram carousel/reel/story, YouTube и Rutube video/short. Типы и ограничения проверяет обычная очередь. Threads video запрещён действующей политикой очереди; это не утверждение об отсутствии API. Короткий пост Дзена пока не поддерживается. Нельзя маскировать неподдержанный формат другим.

Наличие формата не доказывает доступность токена или API. ВК и Rutube используют штатный адаптер и при необходимости ручной пакет. Handed означает передачу, а не публикацию. Delivery вызывает только обычные add/submit: человеческое «Одобрить», commissioning, YouTube первым, HOLD/STOP и один исполнитель остаются в штатном выпуске. Неопределённый исход submit не повторяется вслепую; сверяется точная запись и карточка.

## Стык S3/S0

ProtocolVersion 2 использует queueResults[targetKey]; legacy одиночные задания сохраняют queueResults[channel]. Каноническая сборка экспортируется entryFromIntakeVariant, верификация — verifyIntakeResult. S3 должен разрешать mediaIds=[] для текстовых целей, сохранять targetFacts/inputHash и точный target. S0 синхронизирует по targetEntryName и targetKey. Новые smoke и боевые задания этой проверкой не создавались; развёртывание выполняет S0 после интеграционной проверки.

Уточнение после независимого ревью: если input.targetMedia задан, каждый основной файл обязан происходить от originalmediaId из targetMedia[targetKey], а не просто из общего состава job. Отсутствующий ключ, неверный список или чужой ID блокируют результат. Только legacy без targetMedia использует общий состав. Обложки допускают role publication либо cover, но только того же выбранного исходника, с проверкой материала, MIME, SHA и длины; original запрещён.

S0 добавил src/queue/intake-youtube-first.mjs: разные имена форматов связаны с точным job/revision и квитанцией YouTube. Поэтому временное удержание многоформатного job в verify снято; регрессия проверяет принятие результата и ожидание связанного Reels до подтверждённой премьеры, а также отказ при другом хеше. Порядок add/submit ставит YouTube первым, но сам по себе не заменяет защиту выпуска. Для новых protocolVersion 2 квитанция submitted требует approval.cardHash равный contentHash; legacy карточки без cardHash допускаются только для legacy jobs.
