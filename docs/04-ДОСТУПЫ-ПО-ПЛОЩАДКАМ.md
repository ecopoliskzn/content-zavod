# Доступы: как получить ключ каждой площадки

По шагам, в порядке подключения. Имена переменных взяты из `src/tokens/registry.mjs`; значения кладутся только в файл окружения и нигде больше не появляются. После каждого шага запускается `npm run doctor -- --live`.

Где лежит файл окружения:

- на сервере: `/opt/ecopolis-data/.env`, права 600, владелец `zavod`;
- на компьютере оператора: `.env.local` в корне проекта.

Образец со всеми именами: `.env.example`.

## 0. Сервер, релей и адрес

Порядок установки сервера: `ops/СЕРВЕР.md`. Итог шага: открывается `https://<адрес завода>/health` и отвечает `{"ok":true}`.

## 1. Telegram: бот, группа, канал

**Бот.** Создаёт сотрудник клиента со своего аккаунта.

1. В Telegram открыть @BotFather, команда `/newbot`. Имя: «Экополис». Имя пользователя: например `ecopolis_help_bot`.
2. Токен из ответа BotFather **не пересылается**. Его вводит тот же человек в секреты релея:
   - релей на втором сервере: файл `/etc/zavod-relay.env`, строка `TG_BOT_TOKEN=…`;
   - запасной релей в Cloudflare: `npx wrangler secret put TG_BOT_TOKEN`.
3. У BotFather: `/setprivacy` → Disable. Иначе бот не увидит ответы на карточки в группе.
4. В окружение сервера и компьютера: `TG_BOT_USERNAME` (без @), `TG_RELAY_URL`, `TG_RELAY_SECRET`. Только на сервер: `TG_WEBHOOK_SECRET`.

**Рабочая группа.**

1. Создать группу «Экополис · завод». В настройках включить «Темы».
2. Создать темы: «Согласование», «Заявки», «Отчёты», «Тревоги», «Новости», «Выложить руками».
3. Добавить бота и сделать его администратором.
4. Номер группы, номера тем и номера людей. Утверждающий, его заместитель и ответственный за заявки пишут по одному сообщению в каждой теме, затем на сервере:

   ```bash
   node ops/set-webhook.mjs --who
   ```

   Команда работает только до установки адреса обновлений и тексты сообщений не показывает.
5. В окружение сервера: `TG_GROUP_ID`, `TG_TOPIC_APPROVAL`, `TG_TOPIC_LEADS`, `TG_TOPIC_REPORTS`, `TG_TOPIC_ALERTS`, `TG_TOPIC_NEWS`, `TG_TOPIC_PACKAGES`.
6. `APPROVER_IDS`: номера утверждающего и его заместителя через запятую. `STAFF_IDS`: номера тех, кто берёт заявки.
7. Поставить адрес обновлений и команды бота: `node ops/set-webhook.mjs`.

**Канал.**

1. В канале t.me/ecopolis_kzn: «Управление → Администраторы → Добавить» → бот, право «Публикация сообщений».
2. В окружение: `TG_CHANNEL=@ecopolis_kzn`.

Проверка: `/help` в рабочей группе отвечает списком команд; доктор показывает «бот администратор канала».

## 2. Threads

Подробно, с рисками: `docs/03-META-ЧЕРЕЗ-ПРИЛОЖЕНИЕ-ИСПОЛНИТЕЛЯ.md`, раздел 3.

Итог: `THREADS_TOKEN`, `THREADS_USER_ID`, `THREADS_TOKEN_EXPIRES` в окружении сервера. Маркер живёт 60 дней и продлевается сам (`cron: tokens`).

## 3. ВКонтакте

**Ключ сообщества: текст и ссылка.** Этого хватает для первой публикации.

1. Сообщество → «Управление → Дополнительно → Работа с API → Ключи доступа → Создать ключ». Отметить всё, что предлагает форма.
2. В окружение: `VK_GROUP_ID` (номер сообщества без минуса; виден в адресе раздела статистики), `VK_GROUP_TOKEN`.

**Сервисный ключ: просмотры записей и слежение за чужими стенами.**

1. Кабинет VK ID: id.vk.ru/about/business → создать приложение на аккаунт компании. Адрес возврата: `https://<адрес завода>/cb/vk`.
2. В настройках приложения взять сервисный ключ. В окружение сервера: `VK_APP_ID`, `VK_SERVICE_TOKEN`.

**Ключ администратора: фото и видео.** Путь не проверен боем и зависит от поддержки ВКонтакте.

1. Письмо на devsupport@corp.vk.com от владельца приложения: просьба выдать приложению права `wall`, `photos`, `video` для публикации в собственное сообщество компании. Отправляет клиент.
2. После ответа, на сервере: `node src/tokens/vk-login.mjs --url`. Ссылку открывает администратор сообщества, нажимает «Разрешить» и передаёт оператору две строки со страницы возврата.
3. `node src/tokens/vk-login.mjs --code=<код> --device=<номер>`.
4. `node src/tokens/vk-login.mjs --check`.

Пока шаг не пройден, записи с фото и видео уходят в тему «Выложить руками»: сотрудник клиента вставляет их за две минуты.

## 4. Instagram

Подробно: `docs/03-META-ЧЕРЕЗ-ПРИЛОЖЕНИЕ-ИСПОЛНИТЕЛЯ.md`, разделы 1, 2 и 5.

## 5. Хранилище файлов

1. Кабинет Timeweb Cloud → «Хранилище S3» → создать бакет, тип «Публичный».
2. Создать ключ доступа к бакету.
3. В окружение **компьютера оператора**: `S3_ENDPOINT=https://s3.twcstorage.ru`, `S3_BUCKET`, `S3_REGION=ru-1`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`.
4. Проверка: `npm run doctor -- --media`. Команда загрузит картинку в один пиксель и заберёт её снаружи.
5. Главная проверка: первый рилс. Если Instagram ответит «Media download has failed» три раза подряд, хранилище меняется на Yandex Object Storage (`S3_ENDPOINT=https://storage.yandexcloud.net`, `S3_REGION=ru-central1`): оттуда Meta у нас забирала файлы без отказов.

## 6. YouTube

1. Google Cloud Console на аккаунте компании: создать проект «Экополис завод».
2. «API и сервисы → Библиотека»: включить YouTube Data API v3 и YouTube Analytics API. По умолчанию они выключены.
3. «Экран согласия OAuth»: тип «Внешний», затем **перевести в статус «В продакшене»**. В статусе «Тестирование» ключ живёт семь дней.
4. «Учётные данные → Создать → Идентификатор клиента OAuth», тип «Приложение для компьютера».
5. «Учётные данные → Создать → Ключ API», ограничить его YouTube Data API.
6. В окружение компьютера оператора: `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`, `YOUTUBE_API_KEY`, `YOUTUBE_CHANNEL_ID=UC_yeqCTdrMoziXXELiGtn_g`.
7. Вход владельца канала: `npm run yt -- --login`. Он открывает ссылку в браузере, где вошёл аккаунтом канала, и нажимает «Разрешить». Ключ обновления сам ложится в `.env.local`.
8. Те же пять переменных перенести в окружение сервера.

Проверка: доктор показывает название канала и число подписчиков. Если название не то, вход сделан не тем аккаунтом Google.

**Особенность.** YouTube в России без обходных средств почти не открывается. Загрузка идёт с компьютера оператора, где доступ есть. Сервер обращается только к `googleapis.com`.

## 7. Rutube

1. Завести канал компании на rutube.ru, оформить шапку и описание.
2. С первого дня ролики уходят в тему «Выложить руками»: сотрудник загружает файл в студии Rutube и присылает ссылку. Просмотры завод снимает сам по ссылке.
3. Письмо на help@rutube.ru от владельца канала: просьба прислать документацию API и открыть каналу загрузку роликов по адресу файла. Отправляет клиент.
4. После ответа: `npm run rutube` на созвоне. Логин и пароль вводит владелец канала; пароль на экране не виден и не сохраняется. В окружение ложится `RUTUBE_TOKEN`.
5. Один тестовый ролик через очередь под присмотром.

## 8. Дзен

1. Завести канал компании на dzen.ru, набрать первые десять подписчиков (сотрудники).
2. Студия Дзена → «Настройки → Кросспостинг → Telegram»: взять код.
3. В Telegram открыть бота Дзена, отправить `/sync` и код, добавить бота Дзена администратором канала компании.
4. С этого момента посты Telegram-канала появляются в Дзене сами. Заголовок берётся из первой строки поста: она не длиннее 140 знаков.
5. Статьи, написанные для Дзена отдельно, приходят в тему «Выложить руками».

## 9. Ключ оператора

Связывает компьютер оператора с очередью на сервере.

1. Сгенерировать на сервере. Команда создаёт все случайные секреты, которых ещё нет (ключ оператора, секреты релея и обновлений), и не показывает их:

   ```bash
   node src/tokens/check.mjs --init
   ```

2. Перенести строку `ADMIN_API_TOKEN` в `.env.local` на компьютере оператора по защищённому каналу (scp). Секреты релея тем же путём переносятся в настройки релея.
3. Там же: `QUEUE_API_BASE=https://<адрес завода>`.
4. Проверка: `npm run tokens -- --compare` показывает, что копии совпадают; `npm run queue -- slots` печатает ближайшие слоты.

## 10. После всех шагов

```bash
npm run doctor -- --live --media
```

Ни одной строки с ✗. Строки с ⚠ разобраны: по каждой понятно, почему она есть.

Затем акт передачи доступов (`legal/04`): что выдано, кем, когда, где лежит.
