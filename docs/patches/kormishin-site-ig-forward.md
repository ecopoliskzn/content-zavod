# Правка пересылки событий Instagram на стороне исполнителя

Касается проекта `kormishin-site` (сервер исполнителя), а не завода. Нужна на первый месяц, пока Instagram клиента работает через приложение Meta исполнителя.

**Статус: не применена.** Правка трогает боевой приём событий исполнителя, поэтому вносится отдельным решением владельца проекта. Завод её ждёт только в одной части: ответы на кодовые слова в директе. Всё остальное работает без неё (раздел 6).

## 1. Что не так сейчас

Файлы: `lib/ig/forward.ts` и `app/api/ig/webhook/route.ts`.

У приложения Meta один адрес событий на все подключённые аккаунты. Сервер исполнителя получает событие, смотрит в карту `IG_FORWARD_MAP` и пересылает его дальше. Пересылает **всё тело целиком и с подписью своего приложения**.

Для своих проектов это годится. Для внешнего клиента нет, и причин две.

1. **Подпись.** Чтобы проверить подпись приложения, получателю нужен секрет этого приложения. С секретом приложения можно подделать событие любого аккаунта, который в нём живёт. Отдавать его на сервер клиента нельзя.
2. **Чужие события.** Meta складывает в один запрос события нескольких аккаунтов. Тело, ушедшее клиенту целиком, принесёт ему комментарии и сообщения из чужих аккаунтов. Это переписка людей, которые клиенту ничего не писали.

## 2. Что должно стать

Для аккаунта, у которого задан секрет пары:

- клиенту уходят **только его записи**: из тела остаются элементы `entry` с его номером аккаунта;
- новое тело подписывается **секретом пары**, который знают только сервер исполнителя и сервер этого клиента;
- подпись идёт в заголовке `x-forward-signature`; подпись приложения (`x-hub-signature-256`) не передаётся.

Для аккаунтов без секрета пары поведение прежнее: свои проекты ничего не замечают.

Сервер завода такой заголовок уже понимает: `src/server.mjs`, обработчик `POST /ig/webhook`, переменная `IG_FORWARD_SECRET`. Проверено тестом `test/server.test.mjs`: чужая подпись отклоняется, своя принимается.

## 3. Переменные

На сервере исполнителя:

| Переменная | Что | Пример |
|---|---|---|
| `IG_FORWARD_MAP` | уже есть: номер аккаунта = адрес | `1784…=https://go.ecopolisrf.ru/ig/webhook` |
| `IG_FORWARD_PAIRS` | **новая**: номер аккаунта = имя переменной с секретом пары | `1784…=IG_PAIR_ECOPOLIS` |
| `IG_PAIR_ECOPOLIS` | **новая**: сам секрет пары | 64 знака, создаётся на сервере клиента |

Секрет не лежит в одной строке с адресами: значение секрета и перечень клиентов меняются в разное время и разными людьми. Имя переменной в карте, значение отдельно.

На сервере клиента: `IG_FORWARD_SECRET` с тем же значением. Его создаёт команда `node src/tokens/check.mjs --init`.

**Как секрет попадает с сервера клиента на сервер исполнителя.** Из файла в файл в двух окнах терминала оператора. В чат, письмо и сессию Codex значение не попадает.

## 4. Правка кода

### `lib/ig/forward.ts`

Добавить разбор карты секретов и сборку посылок. Существующие функции `разобратьКартуПересылки`, `разобратьСвоиАккаунты` и `распределить` не меняются: на них стоят тесты и на них держатся свои проекты.

```ts
import crypto from "node:crypto";

/** IG_FORWARD_PAIRS: "id1=ИМЯ_ПЕРЕМЕННОЙ1,id2=ИМЯ_ПЕРЕМЕННОЙ2" → id → значение секрета пары. */
export function разобратьСекретыПар(
  значение: string | undefined,
  окружение: Record<string, string | undefined> = process.env,
): Map<string, string> {
  const секреты = new Map<string, string>();
  if (!значение) return секреты;
  for (const пара of значение.split(",")) {
    const [id, имя] = пара.split("=").map((s) => s.trim());
    const секрет = имя ? окружение[имя] : undefined;
    // Имя есть, а значения нет: пару не заводим. Вызывающая сторона обязана это заметить
    // и НЕ переслать такому получателю тело целиком (см. собратьПосылки).
    if (id && секрет) секреты.set(id, секрет);
  }
  return секреты;
}

export type Посылка = { url: string; тело: string; заголовки: Record<string, string> };

/**
 * Собирает то, что уйдёт каждому получателю.
 *  · у аккаунта есть секрет пары: уходит только его часть тела, подписанная секретом пары;
 *  · секрета пары нет: тело целиком и подпись приложения, как было (свои проекты);
 *  · аккаунт назван в IG_FORWARD_PAIRS, а секрет не нашёлся: не уходит НИЧЕГО.
 *    Отправить такому получателю общее тело значило бы отдать чужие события.
 */
export function собратьПосылки<T extends ЗаписьIG>(
  объект: string,
  записи: T[],
  карта: КартаПересылки,
  секреты: Map<string, string>,
  названыВПарах: Set<string>,
  исходноеТело: string,
  подписьПриложения: string | null,
): Посылка[] {
  const посылки: Посылка[] = [];
  const целиком = new Set<string>();
  const поАккаунту = new Map<string, T[]>();

  for (const запись of записи) {
    const id = String(запись.id || "");
    const url = id ? карта.get(id) : undefined;
    if (!url) continue;
    if (названыВПарах.has(id)) {
      if (!секреты.has(id)) {
        console.error("ig/forward: у аккаунта задана пара, но секрет не найден; событие не переслано", id);
        continue;
      }
      поАккаунту.set(id, [...(поАккаунту.get(id) || []), запись]);
    } else {
      целиком.add(url);
    }
  }

  for (const [id, свои] of поАккаунту) {
    const тело = JSON.stringify({ object: объект, entry: свои });
    const подпись = "sha256=" + crypto.createHmac("sha256", секреты.get(id)!).update(тело, "utf8").digest("hex");
    посылки.push({ url: карта.get(id)!, тело, заголовки: { "x-forward-signature": подпись } });
  }
  for (const url of целиком) {
    посылки.push({ url, тело: исходноеТело, заголовки: подписьПриложения ? { "x-hub-signature-256": подписьПриложения } : {} });
  }
  return посылки;
}
```

Функция `переслать` получает заголовки параметром вместо одной подписи:

```ts
export async function переслать(url: string, тело: string, заголовки: Record<string, string>, таймаутМс = 3000): Promise<void> {
  const контроллер = new AbortController();
  const таймер = setTimeout(() => контроллер.abort(), таймаутМс);
  try {
    await fetch(url, { method: "POST", headers: { "content-type": "application/json", ...заголовки }, body: тело, signal: контроллер.signal });
  } catch (e) {
    console.error("ig/forward: пересылка не удалась", url, e);
  } finally {
    clearTimeout(таймер);
  }
}
```

## 5. Тесты, без которых правку не вносить

В `kormishin-site`, рядом с существующими тестами пересылки:

1. Тело с записями двух аккаунтов, у одного задана пара. Получателю с парой уходит одна запись, подпись в `x-forward-signature` сходится с его секретом, заголовка `x-hub-signature-256` нет.
2. В посылке получателю с парой нет ни одного символа из записи второго аккаунта.
3. Получатель без пары получает исходное тело байт в байт и подпись приложения: поведение прежнее.
4. Аккаунт назван в `IG_FORWARD_PAIRS`, переменной с секретом нет: посылка не создаётся вовсе.
5. Обе новые переменные не заданы: результат совпадает с тем, что было до правки.
6. Сквозной: посылку из теста 1 принимает обработчик завода (`test/server.test.mjs` в этом проекте уже проверяет вторую половину).

## 6. Что работает без правки

| Что | Работает ли до правки | Как |
|---|---|---|
| Публикация рилсов и каруселей | да | вызовы идут с сервера клиента его маркером, пересылка не участвует |
| Кодовое слово в комментарии | да | опрос раз в пять минут: `IG_POLL=1` |
| Кодовое слово в директе | **нет** | событие о сообщении приходит только на адрес приложения |
| Цифры по публикациям | да | вызовы маркером клиента |

То есть первые дни завод идёт без пересылки: слово принимается в комментариях, и подпись ролика зовёт писать его под роликом, а не в директ. Директ подключается после правки.

## 7. Порядок внесения

1. Владелец проекта говорит «да» на правку боевого приёма событий.
2. Правка и тесты вносятся в ветке `kormishin-site`, прогоняются существующие тесты пересылки и бота.
3. Выкладка в тихое время. До выкладки и после: тестовое слово в директе аккаунта другого проекта исполнителя отвечает как раньше.
4. На сервере клиента уже лежит `IG_FORWARD_SECRET`. На сервер исполнителя добавляются `IG_FORWARD_PAIRS`, `IG_PAIR_ECOPOLIS` и пара в `IG_FORWARD_MAP`.
5. Проверка: слово ПРИЁМКА в директ аккаунта клиента с постороннего аккаунта. Ответ со ссылкой в бота приходит в течение минуты.
6. `IG_POLL` на сервере клиента остаётся включённым ещё неделю: два пути не мешают друг другу, повтор ответа одному человеку отсекает журнал отправленного.

**Откат.** Убрать пару клиента из `IG_FORWARD_MAP`: события его аккаунта перестают пересылаться, остальное не затронуто. Код откатывать не нужно.

## 8. Когда правка перестаёт быть нужной

Через месяц аккаунт клиента переезжает на собственное приложение Meta (`docs/03-META-ЧЕРЕЗ-ПРИЛОЖЕНИЕ-ИСПОЛНИТЕЛЯ.md`, раздел 6). События идут на сервер клиента напрямую и подписаны его приложением. Тогда из карты исполнителя убираются пара и секрет клиента, а на сервере клиента удаляется `IG_FORWARD_SECRET`.
