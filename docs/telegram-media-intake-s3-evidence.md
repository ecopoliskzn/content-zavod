## Остаточные риски и безопасный процесс

Неопределённое создание карточки удерживается в unknown: сначала сверка messageId, затем reconcile-card. Невозможность узнать messageId не разрешает слепой дубль. Повреждённый state или неизвестный/живой владелец lock останавливает запись, а не очищает журнал. Если процесс погиб непосредственно при восстановлении recovery-lock, возможна безопасная остановка до технической сверки S0; по таймеру живой lock не снимается.

После смены manifest старый claim должен быть явно освобождён его владельцем; новая версия не захватывается поверх живой. Старый result не меняет новый job. Переходы P7–P13 ведёт существующая очередь; приёмник не заявляет их passed без квитанций. Выход одной площадки не одобряет вторую. Неопределённая внешняя отправка не повторяется вслепую. Детали реального транспорта и выпуска независимо проверяет S0/root.

Межчатовые ответы S0 ранее были отклонены automatic approval review. Обходов через CLI/другие каналы не было; S0 сам прочитал контракт и продолжает интеграцию. Вопросы пользователю не задавались согласно поручению; серверная установка и боевой пилот будут отражены только по подтверждению S0.
