# Контент-завод «Экополис»: правила для каждой сессии

Этот файл Codex читает сам в начале каждой сессии. Здесь то, что верно всегда. Общий план проекта: `МАСТЕР-ПРОМПТ.md`. Правила конкретной сессии: её промпт в `prompts/sessions/`.

## Что это за проект

Завод готовит и выпускает материалы для ООО «Экополис» (Казань, покрытия из резиновой крошки) на восемь площадок: Threads, Telegram-канал, ВКонтакте, Дзен, YouTube, Instagram, Rutube и рассылка в боте. Источник тем: статьи сайта клиента и новости отрасли. Заявки приходят через бота и формы на сервер в России и карточкой в рабочую группу Telegram.

Три машины: сервер клиента в России (очередь, расписание, бот, заявки), релей в Нидерландах (посредник до Telegram и Instagram, ничего не хранит), компьютер оператора (сессии Codex, ролики, дубль расписания, витрина Obsidian). Ты работаешь на третьей.

## Какая ты сессия

Первое сообщение оператора называет сессию: «Сессия S1». Открой её промпт и работай по нему.

## Двенадцать правил, которые не обходятся

**1. Без «Одобрить» не выходит ничего.** Ты не публикуешь. Ты ставишь запись в очередь и отправляешь на согласование; кнопку нажимает человек клиента. «Мелочь», «срочно» и «это же проверка» исключением не являются.

**2. Значение ключа не появляется нигде.** Ни в выводе команды, ни в файле проекта, ни в твоём ответе. Файлы `.env`, `.env.local` и `/opt/ecopolis-data/.env` не открываются и не печатаются. Что задано, показывает `npm run doctor`; отпечатки ключей показывает `npm run tokens`. Ключ между машинами переносится файлом: `npm run tokens -- --export` и `--import`. Если значение всё-таки попало в вывод, остановись и скажи оператору: ключ перевыпускается.

**3. Данные людей не покидают сервер.** Заявки, подписчики бота и переписка лежат в `data/leads/` на сервере. В сессию не попадает ни одна строка оттуда: не читай, не проси показать, не восстанавливай автора комментария. Всё нужное есть в снимке счётом: `mirror/`.

**4. Каждая цифра имеет источник.** Страница сайта клиента, документ клиента либо слова названного сотрудника с датой. Источник лежит в поле `facts` записи. Из головы цифр не бывает: текст выходит от имени производителя покрытий для детских площадок.

**5. Ничего не выдумывается.** Ни заказчик, ни объект, ни разговор, ни отзыв, ни причина. Если в источнике сказано «точку берут не ближе трёх метров от края» и не сказано почему, в тексте причины нет.

**6. Спорные цифры закрыты.** `docs/09-ФАКТУРА-КЛИЕНТА.md`, раздел 7: возраст компании, срок службы, толщина для детских площадок, температура укладки, цены, окупаемость франшизы. Пока клиент не назвал одну версию, их в текстах нет.

**7. На площадках с ограниченным доступом нет предложений.** Instagram, Threads, Telegram, YouTube, рассылка в боте: без цен, акций, «закажите», «оставьте заявку», телефона. Разбор и польза. Предложения идут во ВКонтакте, на Rutube и в Дзен. Основание: `legal/02-РЕГЛАМЕНТ-РЕКЛАМЫ.md`.

**8. Кодовое слово бота живёт только в Instagram.** На любой другой площадке человек напишет слово и не получит ничего. Там стоит прямая ссылка.

**9. У очереди один писатель.** Очередь меняется только командами `npm run queue`. Файлы очереди, журнала и снимка руками не правятся.

**10. Посредников нет.** Сервисы автопостинга, конструкторы ботов и платные сервисы слежения не подключаются. Решение владельца проекта.

**11. Чужие аккаунты не трогаются.** Пароли клиента не запрашиваются и не принимаются. В аккаунт клиента со своего устройства не входим: вход делает владелец на своём телефоне. Старые публикации клиента не правятся и не удаляются без согласованного списка.

**12. Проверку нельзя обойти.** Если `npm run check` остановил запись, правится запись, а не правило и не формулировка «чтобы прошло». Проверка остановила хороший текст: это пример для оператора.

## Порядок работы с материалом

```bash
npm run mirror
```

```bash
npm run queue -- inbox
```

Сначала правки утверждающего, потом новое.

1. Тема из банка `content/topics/банк-тем.md` либо задание оператора.
2. Источник прочитан целиком.
3. Текст по образцу из `prompts/samples/`. Один текст за раз.
4. Проверка фактов: `prompts/samples/фактчек.md`.
5. Ссылка: `npm run link -- --slug=<слаг> --channel=<площадка> --name=<имя записи>`.
6. Файл записи: `content/queue/<площадка>/<дата>/<имя>.json`.
7. `npm run check -- --file=<файл>`: ноль блокирующих и ноль замечаний.
8. `npm run queue -- add --file=<файл>`: слот подберётся сам.
9. `npm run queue -- submit <имя>`.

Имя записи: латиница, цифры и дефис, до 32 знаков. Оно же метка публикации в ссылке.

Спорное решает человек клиента: в запись ставится поле `ask` с вопросом, на который можно ответить «да» или «нет».

## Коды выхода

| Код | Что значит | Что делать |
|---|---|---|
| 0 | сделано | дальше |
| 1 | отказ по правилу: проверка не пройдена, переход запрещён | исправить запись либо ответить человеку. Чинить окружение не нужно |
| 2 | поломка окружения: нет ключа, нет сети, не читается файл | это чинит сессия S0 |

Код 1 и код 2 не смешиваются. Вывод команды выкладки не пускается через пайп: пайп съедает код выхода, и провал выглядит успехом.

## Как писать тексты

Полностью: `docs/07-РЕДПОЛИТИКА.md`. Коротко:

- голос инженера на объекте: что измерил, что увидел, откуда цифра. Себя не хвалит;
- в первой фразе якорь: цифра, объект или названный человек;
- одна мысль на текст;
- первая фраза не вопрос, не «вы» и не подводка («сегодня расскажем», «важно понимать»);
- оборот «не X, а Y» не чаще одного раза на текст; длинное тире не чаще двух;
- доли процентами: «на 20%», а не «на одну пятую»;
- превосходных степеней нет: «лучший», «№ 1», «единственный» требуют документа;
- последняя фраза даёт действие, а не итог прочитанного;
- чужой брак показываем, чужое имя нет; заказчика не называем без разрешения;
- дети не в кадре.

## Как работать с кодом

- Node 20 и новее, модули `.mjs`, без зависимостей и без сборки. Имена файлов и флагов латиницей, комментарии по-русски.
- Сначала тест, который падает на ошибке, потом правка. После правки: `npm test`, `npm run test:bot`, `npm run doctor`, `npm run vault -- --check`.
- Шапка модуля пишется для людей: что он делает и почему так. Витрина показывает её клиенту как есть.
- Код с обратными косыми чертами (регулярные выражения) правится редактором файлов, а не скриптом через командную строку: оболочка теряет их молча.
- Файлы `.cmd` и `.ps1` только латиницей: планировщик Windows кириллицу в них портит.
- Код выхода ставится через `process.exitCode`, без `process.exit()` после сетевого запроса: на Windows это даёт ложный код 127.
- Границы слов в регулярных выражениях для русского текста считаются через `\p{L}` с флагом `u`: `\b` кириллицу не видит.

## Git

- Коммит: файлы перечисляются поимённо. `git add -A` и `git add .` не используются.
- В git не попадают: файлы окружения, `data/`, `mirror/`, `vault/`, `reference/`, ролики.
- Сообщение коммита по-русски: что изменилось и зачем.
- Выкладывается только закоммиченное: `bash ops/deploy.sh zavod@<адрес сервера>`.

## Когда остановиться и спросить оператора

- действие необратимо: удаление, перевыпуск ключа, правка канала или аккаунта клиента;
- для текста нужна цифра, которой нет в источнике, либо цифра из списка противоречий;
- нужно назвать заказчика, сумму договора, конкурента;
- человек в комментарии или в вопросе жалуется, угрожает или пишет о травме;
- задание выходит за границу твоей сессии;
- хочется обойти согласование, расписание или проверку «один раз».

В остальных случаях доводи задание до конца сам и не спрашивай разрешения на каждый шаг.

## Как отвечать оператору

- По-русски. Коротко: сначала ответ, потом подробности.
- Путь к готовому файлу полный, от буквы диска.
- Сделано и проверено: скажи прямо. Тест упал или шаг пропущен: скажи это с выводом.
- Что не проверено боем, называется как непроверенное.
- В конце ответа ровно три следующих шага, пронумерованных 1, 2, 3. Первый — рекомендуемый. Оператору должно хватить ответа «1».
- Без оборотов «мне кажется» и без подводок: вердикт и основание.
